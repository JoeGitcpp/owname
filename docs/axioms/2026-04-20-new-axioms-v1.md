# 语言系统公理 v1

创建日期：2026-04-20
状态：冻结候选

## 目的

本文件用于定义语言系统在整体架构中的正确位置，并纠正当前实现中对 `Naming / Label Layer`、`semantic_readiness`、`symbolizer / concept_id` 的前置化处理。

本文件的目标不是设计一个“更好的 token 系统”，而是明确：

- 什么是语言系统
- 什么不是语言系统
- 它与对象、关系、感知、推理之间的边界是什么
- 后续实现时哪些工程写法会把系统重新拖回基于 token 的人工智能

---

## 阅读保护说明

由于开发任务由大模型执行，后续文档、讨论和代码注释中不可避免会出现这些词：

- `词`
- `字`
- `字符`
- `文本`
- `发音`
- `token`
- `label`
- `name`

这些词在本文中一律按**外部观察术语**理解，而不是按**内部本体单位**理解。

也就是说：

- 当本文说“词”时，指的是外部人类使用的一种符号组合现象
- 当本文说“文本”时，指的是外部可见的符号序列载体
- 当本文说“发音”时，指的是外部可听的声音模式
- 当本文引用 `token / label / concept_id` 时，通常是在描述现有工程命名或要被否定的旧路线

这些词的出现，**不构成**以下任何声明：

- AI 内部以 token 为思维原子
- AI 内部以文本序列为认知本体
- AI 内部先有 label，再有对象
- AI 内部先有离散编号，再等待外部贴词

一句话：

**本文允许借用人类术语进行说明，但严禁把说明术语误读为 AI 本体结构。**

---

## 定位

语言系统不是 tier 0，不是对象层，不是关系层，也不是推理本体。

语言系统的正确位置是：

`外部符号 / 外部声音模式`
-> `绑定与解绑定`
-> `对象 / 动作 / 关系 / 时间结构`

因此：

- 语言系统依赖对象层而存在
- 语言系统依赖关系层而消歧
- 语言系统可以强化认知访问速度
- 语言系统不能成为对象存在的前提
- 语言系统不能反过来定义世界的本体结构

---

## 核心公理

### 公理 1：对象先于名称

对象不是名称，不是词，不是标签，也不是编号。
对象可以在没有名称的情况下先被认出、维持、比较、追踪。

如果一个设计要求“先得到内部词项，才能承认对象存在”，该设计违背本公理。

### 公理 2：关系先于命名

对象之间的相对关系可以先成立，再被压缩指称。

例如：

- “那两个东西靠近”
- “这个声音常跟那个图案共同出现”
- “这个动作通常发生在那个事件之后”

这些关系都可以在没有命名的情况下存在。

### 公理 3：语言不是预置离散符号仓

AI 本体中不应预先设置人为指定的字符表、token 表、label 表、concept_id 表作为语言基础。

语言不能以“先有内部离散占位物，再等待外部贴词”的方式建模。

任何“先编号，再贴义”的路线都只能是工程索引技巧，不能冒充语言本体。

### 公理 4：语言是可学习的绑定现象

语言不是先验模块，而是下列内容在时间中反复共同出现后形成的稳定绑定现象：

- 图案
- 声音模式
- 对象
- 动作
- 关系
- 情境
- 时间结构

所谓“词”只是这些绑定现象在外部观察侧表现出的一种高频、可复用触发形态。

### 公理 5：命名不是资格门，而是压缩指称行为

Naming / Label 的本质不是独立资格层，不是晋级门，也不是编号分配器。

它本质上是：

- 某个外部图案触发某个对象簇
- 某个声音模式触发某个动作脚本
- 某个符号组合触发某种关系结构

也就是一种压缩指称行为，而不是 ontological promotion。

### 公理 6：语言绑定允许从弱到强逐步形成

一个图案、声音模式或书写形式，即使尚未形成深而稳定的长期绑定，也可以先承担临时指称作用。

因此：

- “未完全稳定” 不等于 “不能进入语言过程”
- “只有跨模态完全固化后才允许指称” 不是基础公理

语言形成应允许弱绑定、局部绑定、暂态绑定、可撤销绑定。

### 公理 7：多义性和多表达性是常态

同一个图案或声音模式可以在不同情境下指向多个对象、关系或行为。
同一个对象、关系或行为也可以被多种图案或声音模式指称。

因此语言系统必须天然允许：

- 一词多义
- 多词一义
- 上下文转义
- 歧义待决

任何要求“一个内部离散单位稳定唯一对应一个概念”的设计，都不是语言本质。

### 公理 8：语言层不得反客为主成为世界模型本体

对象层与关系层始终高于语言层。

语言可以：

- 提高访问速度
- 提高沟通效率
- 提高复用性

但语言不能：

- 定义对象是否存在
- 决定关系是否成立
- 替代感知证据
- 替代对象历史

### 公理 9：语言失败不得污染认知本体

命名错误、识别错误、翻译错误、发音映射错误，不应直接改写对象本体。

语言失败最多只能导致：

- 绑定置信度下降
- 新候选绑定产生
- 当前解读被撤销

不能导致：

- 对象被抹除
- 关系被伪造
- 感知事实被语言覆盖

### 公理 10：任何语言绑定都必须可回溯

如果未来保留某种语言缓存、索引或快捷通道，那么它必须可回溯到以下证据之一或其组合：

- 感知片段
- 对象历史
- 关系投影
- 交互经历
- 长期共同出现统计

不能回溯的“意义”不能被视为稳定语言知识，只能视为待验证假设。

### 公理 11：多语言共享对象层，不共享本体

中文、英文、日文或其他书写/发音系统，不应各自拥有一套独立世界模型。

它们共享：

- 对象层
- 动作层
- 关系层
- 时间结构层

它们不共享的只是：

- 外部图案形态
- 外部声音模式
- 局部习惯压缩方式

### 公理 12：语法是关系压缩，不是独立神谕

主谓宾、时态、格、修饰、指代等现象，不应被当成先于对象和关系存在的神谕层。

它们本质上是对象、动作、关系、时间结构在外部符号序列中的压缩投影。

因此，语法层可以作为外部接口层或绑定层的高阶结构存在，但不能成为认知本体的上位裁判。

## 边界定义

### 边界 1：语言系统不属于 tier 0

tier 0 是可测差异方向的坐标底座。
语言系统不是坐标轴，不是 tier 0 元素集合的一部分。

任何试图把“字词类别”“文本标签”“概念编号”塞进 tier 0 的行为，都属于边界越权。

### 边界 2：语言系统不等于对象层

对象层负责承认“有什么存在、在持续、在变化”。
语言系统只负责把外部可见/可听的符号形态与这些已存在的对象结构建立绑定。

对象消失后，绑定应失效。
绑定失效后，对象未必消失。

### 边界 3：语言系统不等于关系层

关系层负责按需投影对象之间的相对几何、时间、动态和高阶互动。
语言系统可以读取这些关系并对其进行压缩指称，但不能取代关系投影机制。

不能因为某个词经常表示某类关系，就把该词当成关系本体。

### 边界 4：语言系统不等于推理层

推理发生在对象、关系、历史和误差修正之上。
语言表达可以触发推理、协助推理、压缩推理结果，但语言序列本身不是推理本体。

如果一个方案把“字符串续写”直接当成“思维过程”，则该方案越界。

### 边界 5：语言系统不是内部编号器

语言系统可以使用缓存、索引、句柄、哈希、候选表等工程结构。
但这些东西只能作为工程加速设施存在，不能被解释成“内部真实词项”。

因此：

- `concept_id` 不是概念本体
- `label_id` 不是语义本体
- `token_id` 不是思维原子

### 边界 6：语言系统的输入边界

语言系统只接收两类上游事实：

- 外部出现的图案和声音模式
- 内部已存在的对象、动作、关系、时间结构

它不能凭空生成一个无对象支撑的“意义单位”并要求底层承认。

### 边界 7：语言系统的输出边界

语言系统的输出只能是：

- 某种绑定候选
- 某种绑定强化
- 某种绑定撤销
- 某种对外符号/声音的生成尝试

它不能直接输出“世界真相已确定”这类越级结论。

## 对当前工程的直接约束

### 必须删除或降级出主流程

- `semantic_readiness` 作为独立“语义资格层”的概念和主流程地位
- `symbolizer`
- `concept_id`
- “稳定对象/关系 -> 分配离散概念编号”的建模方式
- 主刷新链中的 `refresh_semantic_readiness()` 与 `refresh_symbolizer()`
- 围绕上述两层建立的快照字段、observer 输出、合同测试中的本体解释

### 只能保留为辅助统计

以下内容不能再被解释为“进入语言系统的资格”，只能保留为底层统计量：

- 稳定度
- 持续度
- 注意力份额
- 重现度
- 关系强度
- 预测误差
- 对象高层稳定性

这些值最多只能表达：

- 当前是否稳定
- 当前是否高频复现
- 当前是否值得继续跟踪
- 当前是否适合作为绑定候选的证据来源

不能表达：

- 是否已经有语义资格
- 是否应该获得内部概念编号
- 是否已经进入 Naming / Label Layer
- 是否已经“拥有词义”

### 可以保留为底层基底

- `viewport` 作为共享底座
- `ambient` / `slot` / `fusion`
- `relation` 与 relation predictor
- `reasoning` 与 reasoning history
- VIB / PHOT 感知与对应预测器
- slot claim / reuse / spatial 机制
- snapshot 作为外部观察基础设施
- observer 作为外部研发工具

## 防偏移解释规则

以后任何新方案，只要出现以下写法，就必须主动解释它没有越界：

- “token”
- “label”
- “name”
- “concept”
- “semantic”
- “text understanding”
- “word embedding”

解释时至少要同时写清楚四件事：

- 技术描述
- 通俗描述
- 它在整体架构中的边界位置
- 为什么它没有把系统重新拖回 token 本体论

如果写不清这四件事，默认视为方案有偏移风险。

---

## 防偏移自检表

后续任何语言相关设计，都应先做以下自检：

1. 去掉所有词和文本后，对象层还能否继续存在并工作
2. 一个对象能否在长期未命名的情况下被追踪和比较
3. 同一对象换三种语言命名时，底层是否仍是同一个对象
4. 去掉某种语言接口后，对象记忆是否仍保留
5. 句子理解的最终落点是否是对象和关系，而不是字符串改写
6. 发音和文字是否最终指向同一个对象/关系落点，而不是两套独立语义
7. 若把当前所有离散编号删除，系统是否仍可继续形成对象和关系

只要其中任何一条回答为“否”，方案就需要重审。

---

## 当前直接结论

当前实现里最需要优先重构的不是感知模块，而是：

- `viewport.rs` 中的 `semantic_readiness` 与 `symbolizer`
- `body.rs` 中把它们编进正式主循环的调度逻辑
- `snapshot.rs` 和 `observer.rs` 对它们的固化与展示
- 相关合同测试里对它们的本体化假设

感知、对象、关系、注意力、推理历史这些层，大体可以保留为后续重建语言机制的底层基底。

本文件的最终立场只有一句：

**语言系统只能建立在对象与关系之上，不能倒过来成为对象与关系的来源。**
