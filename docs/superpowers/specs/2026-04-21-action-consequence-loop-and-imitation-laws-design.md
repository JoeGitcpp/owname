## 1. 文档定位与边界

这份 spec 从已确认的动作输出 substrate 接口边界出发，继续向上定义动作-后果闭环与早期模仿的抽象法则。

### 1.1 接口起点

上一份 spec 已钉定的 4 类接口前提，是本 spec 的唯一起点：

1. **输出写出状态**：身体至少知道某条输出通道当前在写出什么程度的变化
2. **输出时间结构**：输出有开始、延续、转折、结束的位置，嵌入共享时间骨架
3. **输出可重复与可撤回性**：同类试探可再次发生，也可减弱、终止、换路
4. **输出不自带世界内容裁决**：后续闭环不能把通道层误读为已知目标区、结果区、意义区

### 1.2 本 spec 不定义的内容

本 spec 明确不定义：

- 任何具体输出器官、动作引擎、行为调度器
- 语言绑定层的具体进展
- 可逆捷径正式形成法则（属于后续 spec）
- 自稳、自我调整、局部修复法则（属于再后续 spec）
- 任何说话、唱歌、抓取等具体行为功能实现

### 1.3 高风险术语边界说明

本 spec 中若出现以下词，一律按**外部观察术语**理解，不是内部本体单位：

- `模仿`、`后果`、`比较`、`保持`、`回流`

内部真实允许存在的，仍然只能是：

- predictor / err / precision / update
- 时间窗 / 延迟结构 / 曲线片段
- viewport / 共享时间结构
- 已有 substrate 上的状态变化

这些词之所以不是本体单位，是因为本 spec 讨论的是几条法则如何落到身体已有 substrate 上，而不是在内部新建以它们命名的器官。这种用法不违反最高原则和语言公理，因为本文明确禁止把这些术语变成内部资格门或概念分配器。

## 2. 后果回流法则

### 2.1 输出效果必须能重新进入感知

身体发出的动作输出，其后续物理效果（声音传播、光变化、机械反馈等）必须能够通过感知通道重新进入身体。

这里不要求一个专门的"自感知器官"或"自我感知模块"。正确的架构要求是：

- 身体自身输出变化的物理后果，进入与外界刺激相同的感知 ingress 路径
- 这些信号和外部来源的信号处于同一个 ingress 路径，不需要在进入之前预先区分
- "是否是自己输出造成的"这一区分本身是可学习的，而不是先验本体

因此，不得设计一个专门的"自我感知通路"，在进入身体之前就把自我输出和外部输入截然分开。这种截然分开会把"身体对自己的输出如何造成了世界变化"这一本来可学习的问题，变成工程师预写的区分，违反 Learned Boundaries Only 原则。

### 2.2 回流只是前提，不是闭环

仅仅"感知通道接收到了与自己输出相关的信号"还不构成学习闭环。

闭环还需要：

- 时间配对（Section 3）
- 后果边界识别（Section 4）

因此后果回流法则只处理一件事：**让动作输出的后续物理变化，有资格作为感知信号进入身体。**

### 2.3 输出-感知通路的对称性

一个整体上合理的设计应满足：

- 身体施加出去的变化，如果有物理后果，那些后果能被身体自己的感知通道捕捉
- 捕捉路径是已有的感知 ingress，而不是新建的"自感知专用路径"
- 感知通道的已有 predictor / err / precision 机制，同样适用于处理这些回流信号

换言之：**输出写出能力是感知能力在方向上的反向展开，而不是一套独立系统。**

## 3. 动作-后果时间配对法则

### 3.1 时间配对是可学习的，不是固定窗口

动作（探针输出）与后续感知变化之间的时间关联，不能由工程师预先设置一个固定"响应窗口"。

正确做法是：

- 系统在时间中同时维持：当前输出状态、历史输出曲线、当前感知变化流
- 学习哪些感知变化与哪类输出在时间上稳定共现
- 这种共现统计的时间窗，由历史耦合强度逐步形成，不被写死

原因：不同物理效果有不同延迟（声音反馈快，某些机械效果慢，某些行动后的世界变化持久而缓慢）。固定时间窗只能学到适合该窗口内的耦合，其他时间尺度的后果会被系统性遗漏。

### 3.2 延迟结构的最小要求

时间配对机制最低需要能处理：

- **短延迟**（毫秒级，如声音回响）
- **中延迟**（秒级，如物理反应传到感知通道）
- **尾波与残留效应**（输出停止后，感知信号仍持续一段时间）
- **多次探针的叠加**（两次探针的后果可能在时间上交叠）

因此时间配对不是"发出探针 → 等 N 毫秒 → 收结果"，而是：

**维持一个持续的、多尺度的时间关系学习过程，在其中找出哪些感知变化与哪类输出之间有稳定的时间结构。**

### 3.3 配对归因是可修正的

初始的时间配对判断可能是错误的。

系统可能把碰巧同时发生的感知变化归入某次探针的后果，而后续探索证明这一配对不稳定。这种配对归因失败必须可以：

- 降权已有的时间关联假设
- 恢复待决状态
- 在后续探索中重新收敛

因此时间配对不是一次性判断，而是随着探索历史不断更新的动态结构。

### 3.4 禁止固定后果窗口

不得在实现中写：

- "探针发起后的 N 毫秒内收到的信号算后果"
- "超过 X 毫秒不算同一次作用链"
- 类似的固定时间门

这些固定写法会把"时间耦合结构"变成工程师预写的世界内容，违反 Learned Boundaries Only 原则。

## 4. 后果边界形成法则

### 4.1 后果边界是学习历史的结果，不是先验分类

探针发出后，世界中会发生各种变化。哪些变化属于这次探针的"后果"，哪些只是无关背景噪声，不能被工程师预先写死。

正确的写法是：

- 系统同时维持：当前探针的输出曲线、当前所有感知通道的变化流
- 通过历史上哪些变化与这类探针稳定共现，逐步识别出稳定耦合区
- 稳定耦合区就是当前学习历史下的"后果边界"
- 这个边界会随探索继续而漂移、扩张、收缩或被重构

### 4.2 后果边界的暂时分层结构

虽然边界本身是可学习的，但在当前学习状态下，可以存在暂时的分层：

- **中心区**：当前与这类探针耦合最稳定、最高频的感知变化
- **边缘区**：反复出现但耦合不那么稳定的感知变化，仍处于学习中
- **外围**：长期无稳定耦合的感知变化

这三层不是固定分类，而是当前学习状态下的暂时结构。"中心""边缘""外围"是可漂移的，不是永久字段。

### 4.3 边界形成不依赖内容预设

后果边界不得通过以下方式形成：

- 工程师预先划定"这类探针只影响这片对象区域"
- 预先写定"这种输出的主要后果是什么"
- 预先分配"目标结果 / 邻近结果 / 意外结果"这样的静态分类

边界的形成**规则**可以预设（稳定耦合优先、边缘漂移更新），但**内容**不能预设。

## 5. 外部模式短时保持法则

### 5.1 保持不是独立缓冲器

模仿要求系统在接收到外部连续模式之后，能在一定时间内对这个模式进行某种程度的保持，以便与自身输出进行比较。

但这个"保持"不应被理解为：

- 一个独立的"模式缓冲器"
- 一个"输入记忆模块"
- 一个先读取外部模式再等待比较的独立子系统

更符合本架构的理解是：

**外部模式的短时保持，是现有时间结构中 predictor / history 机制的自然延伸——在当前时间窗内，这段外部曲线仍然处于活跃状态，就像任何其他尚未完全更新完的感知曲线一样。**

### 5.2 保持时长本身是可学习的

外部模式应保持多长时间，不能被固定成一个常数。

不同的外部模式有不同的时间特征：短促的声音模式、持续的视觉模式、节律性重复的模式……系统应在历史中逐步学会对不同类型的外部模式，哪种保持时长最有助于后续逼近成功。

### 5.3 保持不等于忠实复制

"短时保持"不要求系统在内部以完全精确的形式重建外部模式。它只需要：

- 该模式的曲线特征（时序结构、幅度轮廓、节律关键点）在当前时间窗内仍然是可访问的活跃预测约束
- 这个约束足以被用来与自身输出做比较
- 保持精度本身是可调的，不是固定的

## 6. 自他比较法则

### 6.1 比较是曲线比较，不是语义比较

自身输出与外部模式之间的比较，不能在语言层、语义层、词义层进行。

比较的最小正确形式是：

**在时间曲线层面，自身当前正在产生的输出曲线，与仍处于活跃状态的外部模式曲线之间，在多个 tier 0 轴上存在的差异。**

这个差异本质上就是预测误差（err）：系统以外部模式曲线为目标来约束自己的输出预测，误差越大说明逼近越差，误差越小说明逼近越好。

### 6.2 比较使用已有 predictor/err 机制

这意味着"自他比较"不是一种新机制，而是已有 predictor / err 范式在新方向上的应用：

- 外部模式曲线暂时扮演"目标"的角色（不是语义目标，而是曲线形态目标）
- 自身输出曲线产生预测
- 差异形成 err 信号
- err 信号反馈到更新机制，驱动输出曲线朝目标逼近

### 6.3 自他区分本身是可学习的

系统不需要在底层就预先知道"这是我的输出，那是外部的输入"。

这一区分应从以下历史中逐步形成：

- 自身输出通常与动作写出状态（自身可见）强烈共现
- 外部模式通常来自感知 ingress，不与自身写出状态共现
- 系统可以在统计层面逐步区分哪些曲线更可能是"自己刚才写出的"，哪些更可能是"外部来的"

这种区分不是先验本体，而是动作历史与感知历史的统计分离结果。

### 6.4 比较质量是可学习的更新偏置

系统在历史中会发现，对某些时间轴、某些频率成分的比较，更能有效驱动模仿收敛。这些有效比较维度应获得更高的 precision 和更新优先级。

但这些优先级维度不是 tier 0 新轴，不是语言单位，不是概念单位，而是学习过程中形成的更新偏置。

## 7. 模仿作为曲线逼近的法则

### 7.1 模仿的最小形式

本架构中，模仿不需要语言理解、不需要意义识别、不需要符号匹配。

它的最小形式只有 5 步：

1. 外部模式（时间曲线）进入感知
2. 该模式在当前时间窗内被短时保持
3. 身体产生近似形态的输出曲线
4. 系统比较自身输出曲线与外部模式曲线的差异（err）
5. 该 err 驱动输出曲线朝外部模式继续逼近

这就是模仿的底层闭环。它首先是曲线逼近，不是语义理解，不是社会行为复制，不是意志性模仿。

### 7.2 从 babbling 到逼近的连续过渡

系统不是先"决定要模仿什么"再开始模仿的。更符合本架构的发展路径是：

- 系统持续发出各种低成本探针（babbling 阶段）
- 某次探针的输出曲线碰巧与正在活跃的外部模式曲线相近
- 比较产生了相对小的 err
- 这条探针路径获得更高的 precision 与更新强度
- 后续系统倾向于在相同外部模式出现时再次沿此路径试探
- 逼近精度随历史逐步提高

因此"模仿"不是在某个时刻突然"学会"的能力，而是从 babbling 出发，沿着 err 驱动逐步收敛的过程。

### 7.3 模仿不是单次配对，而是时间过程

系统不是"读取外部模式 → 一次性复制输出"。模仿是一个持续迭代的时间过程：

- 每次输出都可以比上次稍微更接近外部模式
- 也可以暂时更远（探索新方向）
- 长期看，路径中哪些方向更能减小 err，就被历史强化

这意味着模仿行为本身是一条学习曲线，而不是一次性成功或失败的技能测试。

### 7.4 模仿的"够好"边界在逼近中形成

系统不预先知道"什么叫做模仿足够好"。

这个边界来自：

- 历史上哪种 err 水平之后，外部反馈支持了继续这条路径
- 哪种 err 水平之后，外部反馈不再支持继续逼近

"够好"的边界是在学习中形成的，不是工程师预设的固定阈值。

### 7.5 语言不是模仿的来源

早期模仿先于语言绑定。

系统首先模仿的是外部时间曲线和模式结构，而不是"话语意义"。语言绑定只能在对象-关系-动作历史已经足够丰富之后，作为对这些历史的压缩访问方式形成。因此：

- 如果一个设计要求先有内部词义才能开始模仿，那就是倒置了发展顺序
- 语言层不得充当模仿行为的生成根源
- 模仿的发生不需要语言资格门

## 8. 五条法则共享同一 substrate，不形成独立模块

### 8.1 不得从现象名造模块

以下都是外部观察术语，不得由此造出内部模块：

- `后果回流器`
- `时间配对器`
- `模式保持缓冲`
- `自他比较器`
- `模仿引擎`
- `imitation_module`
- `echo_loop`
- `feedback_collector`
- `consequence_window`

这类命名把观察术语误当内部本体，直接违反 cleanup spec §8.1。

### 8.2 法则落点：已有 substrate 的方向扩展

| 法则 | 正确落点 |
|---|---|
| 后果回流 | 已有感知 ingress + predictor / err / precision（无需新通路，只需动作输出的物理后果进入现有路径） |
| 时间配对 | 已有多层时间结构（master_tick、ring history、各层 last_*_t_us）+ 现有统计学习机制 |
| 外部模式保持 | 已有 viewport 时间窗 + 已有活跃 slot / history 机制的自然延伸 |
| 自他比较 | 已有 predictor / err 机制（只需允许"外部模式曲线作为临时预测约束"，不是新造比较器） |
| 曲线逼近 | 已有 precision 调制 + 已有 VPC 更新机制的方向扩展 |

因此，这组法则的正确实现方向是：

**在已有 cleaned substrate 上，让这些法则有正式落点；而不是新造独立子系统。**

## 9. 与当前 cleaned substrate 的映射与真实缺口

### 9.1 已经具备的前提

当前 cleaned substrate 已具备若干与本 spec 直接相关的底座条件：

- **感知 ingress 路径**（VIB / PHOT / MECH adapter）已存在，可接收物理信号，无论来源
- **predictor / err / precision / update 机制**已存在，且可在新方向上被扩展
- **多层时间结构**（master_tick、ring history、各层时间痕迹）已存在，后果回流可进入此骨架
- **snapshot / observer 分离原则**已成立，保证观察工具不反向污染身体本体
- **数值型、曲线型 substrate 风格**已存在，动作-后果闭环的后续写法应保持此风格

### 9.2 只有雏形、尚未正式化的部分

- **动作写出状态**：来自上一份 spec 的缺口，仍未正式补齐；输出-感知对称性暂时还不存在
- **输出侧与感知侧的时间结构对称性**：当前只有感知侧有正式 substrate，输出侧尚无同等地位

### 9.3 当前明确缺失的关键落点

以下关键缺口按本 spec 合同逐项列出：

#### 9.3.1 缺少输出后续变化与输出历史的时间配对机制

当前系统有感知历史，但没有"动作发出之后对应感知变化"的正式时间关联结构。也就是说，系统现在能回答"世界里发生了什么"，但还不能回答"我的试探之后，哪些变化跟着出现了"。

#### 9.3.2 缺少可学习后果边界的正式 substrate

当前系统没有一个专门承载"探针后哪些感知变化稳定耦合"的历史统计结构。后果边界的形成条件虽然在法则层已被定义，但还没有正式代码落点。

#### 9.3.3 缺少外部模式保持的正式约束

虽然 viewport 的时间窗机制可以延伸，但还没有正式定义"当前活跃的外部模式曲线如何在时间窗内保持可访问"。这个缺口不是要求新造缓冲器，而是要求现有 substrate 有正式的"外部曲线暂时活跃"表示。

#### 9.3.4 缺少把外部模式临时作为预测约束的合同

当前 predictor 的目标来自内部历史预测，还没有一个正式机制允许"把外部模式曲线临时设为当前预测约束"。这需要 predictor 的目标来源在一定条件下可以从内部切换为外部曲线。

#### 9.3.5 缺少输出侧 err 信号进入 VPC 更新的正式路径

即使未来自他比较产生了 err，这个 err 如何进入 VPC 更新机制（precision 调制、权重更新）目前还没有正式路径。这意味着曲线逼近目前只是法则方向，而不是现成能力。

### 9.4 判断

当前 cleaned substrate 已经足以承载这些法则的研究，但在输出侧各层正式 substrate 仍然缺失。

正确的下一步方向，不是直接实现模仿行为，而是：

**先让后果回流、时间配对、外部模式保持、自他比较的 substrate 在系统中有正式落点，再让模仿从这些落点中自然长出。**

## 10. 与下一份子 spec 的接口边界

### 10.1 本 spec 负责到哪里

本 spec 只回答（在法则层面）：

- 动作输出之后，身体如何通过感知回流得到后果信号
- 动作与后果如何在时间中配对
- 后果边界如何形成
- 外部模式如何短时保持
- 自身输出如何与外部模式比较
- 模仿如何作为曲线逼近出现

本 spec 不回答：

- fast-path 如何正式形成
- 稳定的模仿历史如何被压缩为快速通道
- 如何定义局部退化与修复
- 具体输出器官如何实现
- 任何高层行为调度问题

### 10.2 下一份子 spec 的起点

下一份子 spec 应以 **自稳、自我调整与局部修复法则** 为主题，专门回答：

- 什么构成局部退化
- 什么是整体不稳
- 何时应降级处理
- 何时应重路由
- 何时应重学
- 历史稳定路径如何被优先回归
- 可逆捷径如何从成功历史中自然压缩出来

### 10.3 两份 spec 之间共享的接口前提

两份 spec 之间只共享以下接口前提：

1. **动作-后果耦合历史**：系统已积累了探针类型与感知变化之间的统计关联
2. **时间配对结构**：已有关联的时间位置信息（开始、延迟、尾波等）
3. **曲线逼近历史**：某些模仿路径已开始出现正反馈，某些路径已被多次打脸
4. **边界暂时结构**：当前学习状态下，哪些后果属于中心区、哪些属于边缘区

这 4 点是接口前提，不是下一份 spec 的全部内容。

### 10.4 本 spec 硬禁令

- 禁止从现象名直接造模块（`后果回流器`、`模仿模块`等）
- 禁止把比较机制做成语义层比较
- 禁止固定后果时间窗为常数
- 禁止把模式保持做成独立缓冲器
- 禁止把"自他"区分做成先验本体
- 禁止预写后果分类（主结果、意外结果等静态字段）
- 禁止让语言层参与模仿的生成根源
- 禁止把"模仿成功"的边界写成固定阈值
- 禁止把学习关注维度误写成 tier 0 新轴或本体新层
- 禁止把这条闭环写成 request/response 式的离散步骤

## 11. 开发准入与防偏移禁令

### 11.1 禁止从三条现象名造三套系统

"后果回流""时间配对""曲线逼近"都只是同一组法则在不同观察视角下的命名。不得因此造出三套独立实现系统。

### 11.2 禁止把固定时间窗当作学习近似

固定时间窗（"N 毫秒响应期"）不是"学习结构的近似实现"，而是根本性的错误路线。它把本该在历史中形成的耦合结构，提前压成工程师写死的参数，违反 Learned Boundaries Only。

### 11.3 禁止把后果回流写成"反向通路"

不得设计一条专用的"反馈通路"或"自感知专线"把输出效果送回来。正确做法是让动作输出的物理效果进入已有感知 ingress，而不是绕开感知路径走一条新通道。

### 11.4 禁止跨越法则层直接实现行为

在动作-后果闭环的 substrate 层正式成立之前，不得直接实现：

- babbling 式重复输出
- 模仿比较行为
- 输出后果归因
- 自他曲线逼近

否则只会得到伪闭环：看上去像在学，实际上底层写出能力与后果回流机制仍未正式成立。

### 11.5 禁止让 observer 需求反推 body 本体

不得因为研发需要"更容易看懂模仿过程"就在 body 里加入：

- 人类可读的模仿日志
- 文本说明
- 面向观察者的功能字段

动作-后果闭环的状态若进入 snapshot，也必须保持数值型、时间型、可回看 substrate 形态，而不是转译成人话。

## 12. 收束结论

这份 spec 的结论同样必须保持克制：

- 动作-后果闭环不是功能系统，而是由后果回流、时间配对、后果边界形成、外部模式保持、自他比较这几条法则共同定义的结构性条件
- 模仿不是高层社会行为的复制，而是曲线逼近：外部模式保持 + 自身输出 + 比较 err + 更新 + 再逼近
- 这五条法则都应落到已有 cleaned substrate（predictor / err / precision / viewport / time structure）上，而不是造出独立子系统
- 当前系统已具备承载这些法则研究的上游条件，但输出侧与输入侧仍不对称，闭环的完整 substrate 尚未成立
- 后续方向应是在 substrate 层正式让这些法则有落点，而不是跳跃到模仿行为实现

**因此，动作-后果闭环的正确研究顺序是：先把法则写清楚，再补 substrate，再让模仿从历史中逐步长出；而不是先预设一套模仿功能，再倒推出一套底层系统。**
