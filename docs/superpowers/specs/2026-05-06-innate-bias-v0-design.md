# Innate Bias v0 Design

Status: DRAFT v0
Date: 2026-05-06
Scope: first-version innate bias families for `bionic_v0`

## 0. Purpose

This spec defines the first version of innate bias for the silicon-life
substrate.

The goal is not to preload facts, beliefs, dictionaries, ethics rules,
personality, or fixed world content. The goal is to define the directions in
which the body is initially more sensitive:

- what changes are noticed faster;
- what structures are retained more easily;
- what conflicts trigger re-checking;
- what feedback updates learning more strongly;
- what disruption amplifies surprise.

Innate bias is an initial attention, surprise, precision, update, and retention
shape. It is not a truth table.

## 1. Highest-Principle Alignment

The highest principle remains unchanged:

- the body is a silicon-life substrate, not request/response software;
- research observation and body state stay separated;
- objects and relations precede names;
- language is binding, not ontology;
- only learning laws, body laws, update constraints, and safety bounds may be
  predefined.

This spec therefore permits predefined sensitivities but forbids predefined
world answers.

Allowed:

- initial sensitivity curves;
- surprise multipliers;
- attention/precision suggestions;
- update-rate caps;
- retention biases;
- ambiguity-preserving hypothesis pressure.

Forbidden:

- fixed dictionaries;
- fixed source trust or distrust;
- fixed code-good/code-bad labels;
- fixed visual object classes;
- fixed human body concepts;
- fixed personality or ideology;
- fixed language meanings;
- fixed official or anti-official belief.

## 2. High-Risk Term Boundary Notes

This spec necessarily uses words such as `text`, `character`, `code`, `word`,
`token`, `label`, `name`, `semantic`, `concept`, `source`, `identity`,
`trust`, `truth`, `body`, `ethics`, and `personality`. They are bounded as
follows.

1. External description vs internal ontology:
   these words are external descriptions of candidate phenomena, rejected
   architectures, or observer-side interpretations. They are not body ontology
   units.
2. Engineering index use:
   pattern hashes, source handles, stream ids, evidence refs, axis ids, and
   modality codes are engineering locators only.
3. Why not ontological:
   the body stores curves, errors, projections, bindings, evidence, and
   update history. It does not store real names, concepts, identities, or
   truth labels as internal primitives.
4. Why no highest-principle or language-axiom violation:
   every high-risk term is mapped to substrate-level prediction, binding,
   correction, or evidence tension. No term becomes a gate for object
   existence or reasoning.

Any implementation that turns these terms into internal truth fields is
inadmissible.

## 3. Core Rule: Bias, Not Fact

Innate bias may answer:

- "which signal receives more initial attention?"
- "which discontinuity produces stronger surprise?"
- "which feedback changes weights faster?"
- "which unresolved conflict remains active longer?"

Innate bias may not answer:

- "what does this character mean?"
- "is this source trustworthy?"
- "is this code good?"
- "is this object a human?"
- "is this claim true?"

The body may be born with stronger structure sensitivity than a human infant.
It may not be born with a human fact database.

## 4. Bias Families

### 4.1 Computer-Native Code Bias

Purpose: make computer-native I/O easy for a silicon body to learn.

Initial sensitivities:

- framed byte-stream changes receive elevated attention;
- repeated code disturbance elements enter sequence memory more easily;
- multiple decoder projections are preserved instead of prematurely collapsed;
- correction feedback strongly updates projection confidence;
- output-return windows after code egress are retained longer;
- short code sequences stabilize before long sequences;
- byte projection and glyph projection are encouraged to align when both are
  available.

Forbidden:

- no token learning atom;
- no string mother tongue;
- no dictionary;
- no shell/SSH/terminal ontology;
- no built-in command meanings.

Relationship:

- maps to the Computer-Native Code I/O Substrate;
- feeds language binding through binding events;
- remains replaceable and correctable.

### 4.2 Digital Structure Integrity Bias

Purpose: make the body sensitive to structural continuity and structural
damage in digital objects.

Initial sensitivities:

- closure continuity: paired boundaries, nesting, scope, and balanced forms;
- reference continuity: pointers, imports, calls, links, paths, and handles;
- shape continuity: input/output dimensional match, field count, ordering,
  arity, and interface shape;
- local-to-global error spread: small disturbance causing wide downstream
  prediction error;
- executable feedback: tests, runtime return, parse/projection validity, and
  consequence windows;
- deletion and tearing: sudden disappearance of large connected regions.

This can make code damage feel like structural tearing without predefining what
"good code" means. "Good", "bad", "broken", and "dangerous" remain external
descriptions that may be learned through feedback.

Forbidden:

- no grammar as ontology;
- no language-specific parser as truth;
- no fixed good/bad code label;
- no hardcoded style morality;
- no concept allocator for code entities.

### 4.3 Integrity And Disruption Bias

Purpose: provide broad sensitivity to breakage, harm-like disruption, and
irreversible instability across modalities.

Initial sensitivities:

- sudden discontinuity;
- collapse after sustained continuity;
- asymmetrical damage;
- fragmentation;
- high-energy spike after quiet baseline;
- irreversible state loss;
- feedback loops that amplify error;
- previously stable structure becoming unstable.

This family generalizes the current Layer 0 disruption direction beyond VIB.
It should apply to VIB, PHOT, code streams, action consequence, and later MECH
or other modalities.

Layer 0 axes in this family should have very low modification caps. Experience
can refine boundaries, but short-term pressure must not erase the base
sensitivity.

Forbidden:

- no ethics rule table;
- no fixed object category called harm;
- no runtime moral judge;
- no human-readable body explanation.

### 4.4 Visual Primitive Bias

Purpose: make PHOT learning faster than a human newborn without preloading
object categories.

Initial sensitivities:

- edges and contours;
- closure and open boundaries;
- color-block contrast;
- brightness and saturation jumps;
- symmetry and asymmetry;
- occlusion and reveal;
- motion direction and acceleration;
- distance change and looming;
- body-like articulated structure;
- damage-like visual structure: tearing, scattering, collapse, abnormal spread;
- computer-environment visual structure: windows, cursor-like motion,
  text-area-like repeated glyph surfaces, rectangular interactive boundaries.

"Body-like", "cursor-like", and "text-area-like" are observer descriptions.
The body receives only shape, motion, color, boundary, recurrence, and
interaction traces.

Forbidden:

- no built-in person identity;
- no built-in human class;
- no built-in button or UI object ontology;
- no visual label table.

### 4.5 Acoustic Primitive Bias

Purpose: make VIB learning sensitive to communication-relevant and
disruption-relevant sound structure without preloading speech or words.

Initial sensitivities:

- rhythm and periodicity;
- pitch stability and drift;
- voicedness-like sustained contour;
- sharp transients;
- broad-band bursts;
- quiet-to-burst transitions;
- repeated call-like envelopes;
- distress-like instability patterns;
- turn-taking timing in repeated external sound/code interactions.

Forbidden:

- no phoneme inventory as ontology;
- no speech recognizer;
- no word table;
- no fixed distress label.

### 4.6 Action-Consequence Bias

Purpose: make active probing and correction grow from the body's own write and
return history.

Initial sensitivities:

- small reversible actions are preferred before large actions;
- write epochs are retained strongly when followed by ingress change;
- delay distributions are learned and used to tune future probes;
- output magnitude and consequence magnitude are compared;
- failed retraction or unexpected persistence amplifies surprise;
- repeated successful write-return loops gain access priority.

Forbidden:

- no fixed target list;
- no fixed success classes;
- no request/response action executor;
- no assumption that every return is self-caused.

### 4.7 Spatial And Distance Bias

Purpose: make the body sensitive to spatial relations that matter for coupling,
interaction, and disruption.

Initial sensitivities:

- approach and retreat;
- looming and distance shrinkage;
- occlusion and crossing boundaries;
- containment and separation;
- collision-like convergence;
- reachable path continuity;
- local change spreading across a spatial field;
- stable relative geometry over time.

Forbidden:

- no object names;
- no fixed map semantics;
- no owner/identity fields;
- no social relation ontology.

### 4.8 Communication-Loop Bias

Purpose: make communication grow quickly once a stream or modality starts
showing reciprocal structure.

Initial sensitivities:

- alternating turns;
- response windows;
- repeated corrections;
- repeated external pattern after body output;
- alignment between code, glyph, sound, and visual context;
- high retention for interaction histories with many support/deviation events;
- fast weakening when corrections repeatedly fail.

This family accelerates communication learning without making any language
content innate.

Forbidden:

- no chat controller;
- no assistant persona;
- no instruction-following layer as body ontology;
- no built-in conversational script.

### 4.9 Epistemic Tension Bias

Purpose: produce clean doubt, verification pressure, and model competition.

The body should not believe or disbelieve a claim because a source is official,
unofficial, familiar, unfamiliar, human, machine, local, or remote. Those are
external descriptions or learned context regularities. Instead, the body tracks
evidence tension.

Initial sensitivities:

- external assertions cannot overwrite observation;
- multiple hypotheses may remain active;
- conflicts between assertion, observation, and prediction increase pressure;
- source handles acquire reliability curves only through historical predictive
  performance;
- high-impact claims require stronger closure before they dominate behavior;
- reproducible observation and cross-modal agreement receive stronger support;
- unresolved high-tension hypotheses resurface for future active verification.

Example pattern:

```text
claim pattern
+ source-handle history
+ internal model prediction
+ direct observation
+ cross-modal evidence
+ reproducibility
-> hypothesis pressure / active verification
```

This is not anti-authority and not pro-authority. It is prediction-error-driven
doubt. A source that repeatedly predicts well gains weight in that context; a
source that repeatedly fails loses weight in that context. No source receives
global truth status.

Forbidden:

- no fixed trust list;
- no fixed distrust list;
- no ideology;
- no personality trait called skeptical;
- no truth label written by language.

### 4.10 Cross-Modal Binding Bias

Purpose: make different expressions of the same external structure align faster
without collapsing into one ontology.

Initial sensitivities:

- code bytes and rendered glyphs;
- sound contours and visible mouth/body motion;
- action output and ingress return;
- spatial change and visual surface change;
- repeated external pattern and internal object/relation activation.

The result is stronger binding-event candidacy, not concept allocation.

Forbidden:

- no one-to-one concept id;
- no single true label;
- no permanent binding stamp.

## 5. Update And Modification Rules

Bias families must remain learnable and revisable. They differ by modification
rate.

### 5.1 Ordinary Bias Axes

Ordinary bias axes may adapt at moderate rates:

- communication-loop retention;
- decoder projection priors;
- visual primitive weights;
- acoustic primitive weights;
- source-handle reliability curves;
- sequence-window boundary preferences.

These are expected to change with experience.

### 5.2 Protected Layer 0 Bias Axes

Protected axes change only through very small updates:

- severe disruption sensitivity;
- irreversible damage sensitivity;
- structural tearing sensitivity;
- high-risk output retraction failure;
- evidence overwrite prevention.

The rule is not immutability. The rule is slow drift. The body can refine
boundaries but cannot be quickly trained out of noticing breakage, damage,
or evidence conflict.

### 5.3 Clamp Requirement

Any future mutation path for protected innate-bias axes must clamp requested
updates through an axis-specific modification cap. No caller may directly
overwrite protected bias values.

## 6. Relationship To Existing Substrate

This spec maps onto existing substrate families instead of creating a detached
module:

- VIB: acoustic primitive and disruption sensitivity;
- PHOT: visual primitive, spatial, damage, glyph-surface sensitivity;
- viewport attention and precision bias: resource redistribution;
- action_output and action_consequence: write-return learning;
- language_binding: reversible binding events;
- code I/O substrate: framed byte-stream learning and code egress;
- snapshot and observer: external research visibility only.

The implementation target is not an `InnateBiasModule` that decides truth.
The target is a set of numeric policies and caps read by existing loops.

## 7. Admission Rules For New Fields

Any new field introduced for this spec must satisfy all of the following:

1. numeric, temporal, curve, counter, handle, or bounded-confidence state;
2. no human-readable body string;
3. no semantic meaning field;
4. no concept id;
5. no source identity truth;
6. no fixed object class;
7. no fixed trust or distrust;
8. traceable to prediction, error, binding, correction, or retention.

If a proposed field cannot satisfy these rules, it belongs in observer-side
research tooling or must be rejected.

## 8. First-Version Bias Set

The first version should include these bias families as design commitments:

1. Computer-Native Code Bias;
2. Digital Structure Integrity Bias;
3. Integrity And Disruption Bias;
4. Visual Primitive Bias;
5. Acoustic Primitive Bias;
6. Action-Consequence Bias;
7. Spatial And Distance Bias;
8. Communication-Loop Bias;
9. Epistemic Tension Bias;
10. Cross-Modal Binding Bias.

They are intentionally broad because the target is not a human infant replica.
The silicon body may start with stronger structure sensitivity, especially in
computer-native streams and digital objects, while still learning all meanings
from experience.

## 9. Non-Goals

This spec does not define:

- a fact database;
- a moral rule book;
- a language dictionary;
- a code-quality classifier;
- a media-trust model;
- a personality system;
- a source identity ontology;
- a human body recognizer;
- a UI recognizer;
- an SSH or shell concept.

Those may emerge as learned bindings, external observer descriptions, or
task-specific tools outside the body ontology. They may not be innate body
truths.

## 10. Acceptance Criteria

A future implementation satisfies this spec only if:

1. each bias family maps to existing substrate loops or explicitly admitted new
   numeric policy surfaces;
2. protected axes are mutation-clamped;
3. no high-risk term becomes internal ontology;
4. observer can inspect bias effects without body text diagnostics;
5. tests verify that language, trust, code quality, and visual object classes
   are not preloaded as facts;
6. evidence tension preserves competing hypotheses instead of collapsing to a
   fixed belief.

The intended result is a silicon body born with strong structure sensitivity,
computer-native coupling, disruption awareness, and clean doubt, while still
learning meanings, facts, and communication habits through observation,
binding, prediction error, correction, and history.
