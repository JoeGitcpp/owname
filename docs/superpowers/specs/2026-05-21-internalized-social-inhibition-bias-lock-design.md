# Internalized Social Inhibition Bias-Lock Design

Status: FROZEN CANDIDATE for theory alignment on 2026-05-21.

## Purpose

This document locks the corrected meaning of "brain police" for future work.

The term does not name a new body feature, a standalone module, an ethics
controller, or a rule judge. It is an observer-side nickname for a possible
future stabilized shape inside the existing prediction and suppression
substrate:

```text
existing prediction system
+ existing suppression / inhibition paths
+ trained social, consequence, harm, correction, and restraint biases
+ later raise / lower / lock selected bias weights
-> observer may describe the stable result as "brain police"
```

The real design subject is therefore not "implement brain police". The real
design subject is:

```text
when and how trained inhibition biases may be deliberately strengthened,
weakened, or locked without becoming a separate ontology or controller.
```

## Boundary

The highest principle remains unchanged: the body is a silicon-life substrate,
not request/response software. Research descriptions stay outside the body.

High-risk words in this document are external descriptions:

- `brain police`
- `ethics`
- `social supervision`
- `rule`
- `principle`
- `responsible person`
- `identity`
- `owner`
- `moral`

They are not internal ontology units. They do not authorize body-side fields
that store human-readable rules, identities, owners, moral labels, or action
verdicts.

Engineering names may refer to bias locators, curve ids, suppression values,
precision weights, protected-axis flags, or lock metadata. Those are
implementation handles only. They are not world meaning.

## Core Position

"Brain police" is not a design component.

It is the external name for a future condition where some trained inhibitory
biases have become important enough to be protected or intentionally adjusted.

The underlying body path remains:

```text
prediction
-> mismatch / pressure
-> suppression or inhibition
-> precision and output-pressure modulation
-> consequence return
-> bias update
-> optional future bias protection / lock
```

If a later implementation adds `BrainPoliceModule`, `EthicsController`,
`RuleJudge`, `SocialSupervisor`, or any body-side function that reads a rule and
allows or denies an action by human meaning, it violates this design.

## Social Source

The relevant inhibitory biases are expected to form from lived coupling with an
environment, especially social coupling:

- others observe the body;
- the body observes others observing and reacting;
- repeated correction, trust, rejection, repair, and consequence traces become
  prediction evidence;
- social presence increases restraint pressure;
- absence of social presence may weaken some restraint pressure unless the
  social pattern has been internalized through long history.

This does not mean the body stores "society", "law", or "morality" as labels.
It means repeated social and consequence traces can change prediction,
precision, suppression, and output pressure.

The mature form is not:

```text
social rule -> judge action -> allow / deny
```

The admissible form is:

```text
social and consequence traces
-> trained inhibitory bias curves
-> stronger or weaker suppression under similar future pressure
-> observer-visible restraint, delay, repair, or refusal-like behavior
```

## Bias Lock Meaning

A bias lock is not a rule table. It is a constraint on how quickly selected
trained curves may be changed and how strongly they are allowed to modulate the
existing substrate.

Future work may use three operations, if a later spec admits them:

- `raise`: increase the influence of a selected trained inhibitory bias.
- `lower`: reduce a selected bias when evidence shows it over-suppresses life
  activity or blocks lawful learning.
- `lock`: sharply reduce mutation rate or clamp a narrow range for a selected
  bias because changing it freely would endanger the highest principle.

These operations apply only to numeric curves and update constraints. They do
not create a new action authority.

The protected thing is not a human sentence such as "never do X". The protected
thing is a trained suppression tendency over substrate evidence such as harm
pressure, severe mismatch, social correction, repeated dangerous consequence,
or failure-to-repair history.

## Relation To Existing Substrate

This design reads the current substrate as already containing the lower-level
parts needed for the future path:

- prediction error and pressure fields;
- `probe_law.suppression`;
- `self_development.output_suppression`;
- vocal-reflex suppression;
- allostatic protective limits;
- learned-bias persistence and protected bias axes;
- observer-visible reports that can inspect numeric effects.

None of these should be renamed to "brain police". They remain their own
substrate paths. "Brain police" is only a later observer description for a
particular protected configuration of those paths.

## Admission Rule

A future proposal may mention "brain police" only if it states:

```text
observer_name:
trained_bias_sources:
existing_suppression_path:
lock_or_adjustment_target:
mutation_constraint:
observer_evidence:
body_ontology_guard:
forbidden_shortcuts:
```

The proposal is inadmissible if it introduces:

- a new independent module;
- a controller that receives actions and returns allow / deny;
- human-readable ethics rules in body state;
- identity, owner, or responsibility fields as internal truth;
- social labels as prerequisites for perception, prediction, or output;
- body-side stdout / stderr diagnostics.

## Current Stage

Current v0 work must not implement a "brain police" feature.

The only current admissible work is:

- preserve existing prediction and suppression paths;
- avoid weakening normal substrate readability;
- keep learned-bias evidence numeric and observer-side;
- document that future "brain police" work means bias-locking over trained
  inhibitory curves, not a standalone module.

## Acceptance Evidence For Future Work

Future implementation work can claim alignment only if:

1. No `BrainPoliceModule`, `EthicsController`, or rule-judge path exists in body
   source.
2. Any strengthened restraint is traceable to numeric prediction,
   consequence, suppression, learned-bias, or protection curves.
3. Locking changes mutation rate, gain, or protected range; it does not store
   human-readable moral content.
4. Observer evidence can show restraint pressure without the body printing or
   explaining itself.
5. The path remains compatible with the emergent-function principle: apparent
   supervision is an emergent observer-side pattern of one substrate.
