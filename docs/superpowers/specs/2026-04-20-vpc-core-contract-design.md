## 1. 文档定位

本文件只处理 `VPC 核心合同`，不直接定义完整意识，不直接定义语言层，也不直接定义人格、身份、伦理或远程数字感官。

本文件要冻结的是：

- VPC 最小本体定义
- VPC 的前置依赖
- Viewport 中什么是观察真相，什么是 predictor 发表物
- 预测颗粒度如何跨尺度成立
- 为什么在本架构里 `预测` 可以构成 `推理`
- “事实性”“汇总”“评分”“置信”在本体系中的正确位置
- “等待结果后继续”在脑内如何存在

本文件不把研发期审计原则写成运行时器官。任何“防偏移”“防污染”表述，若出现，也仅作为架构审计语言，不得被实现成 body 内部资格门或规则引擎。

## 2. VPC 收口目标

VPC 收口只做 3 件事：

1. 固定 `VPC 核心合同`
2. 固定 `最小闭环`
3. 固定 `质量检测口径`

本阶段不试图证明：

- 完整高层认知已经成立
- 多模态语言学习已经成立
- 三感官统一实现已经完成
- 身份、自我、人格或伦理层已经成立

本阶段只要求后续所有感官与语言工作都建立在同一套 VPC 理论闭环上，而不是各自发明一套“预测”“误差”“精度”“事实”的私有定义。

## 3. VPC 前置依赖

在进入任何三感官统一实现之前，以下概念必须先冻结：

1. `Viewport 真相合同`
2. `Predictor 合同`
3. `时间对齐合同`
4. `err 定义合同`
5. `update 本地性合同`
6. `precision 合同`

其中 `Predictor 合同` 的 family-level 实现边界，现由 [2026-04-22-vpc-predictor-contract-design.md](./2026-04-22-vpc-predictor-contract-design.md) 固定。

以下内容重要，但不属于 VPC 核心，不应阻塞 VPC 收口：

- ViewportPolicy / personality
- 多模态融合策略
- 语言绑定层
- 伦理、身份、自我模型

以下内容当前明确排除，不允许借道进入 VPC 核心收口：

- 语言理解
- token/词表
- 对外文本生成
- 远程数字感官
- 高层人格叙事

## 4. VPC 最小核心合同

VPC 的最小本体只包含 5 件事：

1. `predict`
2. `observe`
3. `err`
4. `update`
5. `publish`

展开如下：

- `predict`：对某个已声明观察域的未来状态做预测
- `observe`：从同一观察域读取观测真相
- `err`：计算预测与观测之间的偏差
- `update`：predictor 仅用本地可得信息更新自身
- `publish`：把预测结果、误差痕迹和必要的精度/置信痕迹写回共享视口

VPC 是：

- 运行在共享视口中的局部预测闭环
- 一种本地学习机制
- 一种持续运行机制
- 一种时间中运行的机制
- 一种通过视口间接协同的机制

VPC 不是：

- 语言层
- 命名层
- 语义层
- 身份系统
- 对象分配器
- 概念编号器
- observer 展示系统
- 全局 loss + 跨层 BP 的换皮版本

VPC 的最短定义如下：

`VPC 是一种运行在共享视口中的局部预测闭环：predictor 对已定义观察域做短时或长时预测，以同域观测计算误差，并仅用本地信息持续更新自身，再把预测与误差信息写回视口。`

## 5. 跨尺度像素与推理

### 5.1 可声明尺度的像素

VPC 的预测单位不是固定“单点”，而是 `可声明尺度的轴片段像素`。

这个像素可以是：

- `1ms` 的最小片段
- 一段短曲线
- 一段局部结构曲线
- 一个较大时间窗中的关系片段
- 一个更长远规划尺度的结构片段

因此，VPC predictor 不是只会预测“下一点”，而是可以预测：

- 下一点
- 下一短窗
- 下一局部结构
- 下一阶段趋势
- 更长远的规划性结构片段

### 5.2 预测即推理

在本体系中，`预测` 与 `推理` 不做传统符号逻辑意义上的切割。

这里采用的立场是：

- 人类推理本身也未被证明独立于自身认知预测结构
- 因而在本架构中，`推理` 可被理解为多个尺度上的预测、误差传播、关系收束与路径强化

所以：

- 小像素预测对应近场感觉与即时反应
- 中像素预测对应局部关系与动作趋势
- 大像素预测对应结构判断、规划与长远推演
- 超大像素预测对应超长时间尺度的架构级与文明级思考

本 spec 采用如下定义：

`在本架构中，推理就是跨尺度预测的展开、竞争、等待、收束与强化。`

## 6. 事实性、高阶像素与身体内生汇总

### 6.1 系统原初不先验区分事实与虚假

系统最初并不先验拥有“事实/虚假”的二元裁判。

系统先拥有的是：

- 某对象或片段出现了
- 它在若干元素轴上具有某些值
- 它与其他片段是否一致或冲突
- 它是否反复出现
- 它是否能被后续预测支撑
- 它的稳定性、置信度、冲突度、可回返性如何

因此，所谓 `事实性`，不是一个先验标签，而是对象、片段与关系在时间中通过重复观察、跨模态一致、预测成功和反馈修正后形成的高稳定结构。

### 6.2 汇总、评分、置信可以是高阶像素

“汇总栏”“评分栏”“置信度”并不天然是外部程序污染。

当它们满足以下条件时，它们可以被视为 `高阶像素`：

- 可回溯到真实观察片段
- 来自同一预测-误差闭环
- 随经验和反馈连续变化
- 不是离散硬判定
- 可衰减、可冲突、可修正
- 只是高阶结构，不是裁判神谕

只有这种情况下，它们才属于身体的内生推理部分。

相反，如果某些“汇总/评分”仅仅为了 observer 可视化、研发排序、调试表格而存在，且不能回到同一闭环，它们就只是外部观察投影，不属于身体本体。

### 6.3 长进身体不是二元事件

一个对象或关系一旦被感知到，就已经以某种轴值分布形式进入身体。

区别不在于“有没有进入”，而在于：

- 是否足够稳定
- 是否足够一致
- 是否足够高频
- 是否足够低误差
- 是否形成了强路径

因此，“长进身体”不是一次性的布尔事件，而是连续强化过程。真正接近“肌肉记忆”的，是那些长期高频成功、路径极强的部分。

## 7. Viewport 真相合同

Viewport 中的内容必须严格区分为三类：

### 7.1 Observation Truth

这是感官或对象层当前真正观测到的事实，例如：

- 麦克风 band 值
- 摄像头 motion / band 值
- 触摸板位置或压力相关值
- 某 slot 当前实际观测曲线
- 某 relation 当前由底层统计得到的实际值

这部分才是 `observed truth`。

### 7.2 Predictor Publications

这是 predictor 写回来的东西，例如：

- predicted
- last_err
- precision
- predictor 内部推导出的局部状态摘要

这些不是世界真相，只是某 predictor 的发表物。

### 7.3 Observer Projections

这是为了研发观察方便而组织出来的显示投影，例如：

- 热图
- 排名
- 文本摘要
- 统计表
- 排序结果

它们只属于 observer / snapshot 展示层，不得反向定义身体真相。

### 7.4 基本分离原则

本 spec 固定以下三条分离原则：

1. `observation truth` 不得由 predictor 写入
2. `predictor publications` 不得覆盖 observation truth
3. `observer projections` 不得反向要求 body 新增本体字段

这里的分离原则是 `研发期架构边界`，不是 body 内部资格门。

`§7` 的具体实现合同由 [2026-04-22-vpc-time-and-error-contract-design.md](./2026-04-22-vpc-time-and-error-contract-design.md) 固定，后续代码与测试应直接以该子 spec 为准。

## 8. 未闭合预测、等待与继续条件

### 8.1 多个推理并行存在

在本架构中，推理不应被理解为单线程顺序程序。

更准确的理解是：

- 多个不同尺度的预测像素同时存活
- 有些是短时的
- 有些是中程的
- 有些是长程的
- 它们共享对象、关系与时间结构，但各自维持自己的未闭合状态

因此，“多个推理同时进行”本质上就是：

`多个不同尺度、不同目标的预测闭环同时运行。`

### 8.2 等待不是阻塞

AI 脑内的“等待结果后继续”不应被定义成程序式 blocking。

更自然的定义是：

`某个预测链条已经形成下一步期待，但缺少关键观测、关键反馈或关键依赖结果，因此它保持张开状态，暂不闭合。`

所以等待不是空白，也不是停机，而是一种 `未闭合状态`。

### 8.3 继续条件

未闭合预测的继续，通常由以下三类条件触发：

1. `新观测到来`
2. `内部时间窗到点`
3. `其他推理链传来结果`

因此，“等结果再继续”实际上是：

`某条推理链的继续条件尚未满足，先维持；满足后继续收束。`

### 8.4 悬置结构

后续实现中，应为这类结构保留正式位置。它们可以被称为：

- 未闭合预测
- 待证关系
- 悬置结构
- 开放回路

它们共同的性质是：

- 已经进入身体
- 但尚未收束成强路径
- 有自己的时间范围
- 有当前置信和依赖结构
- 可被新证据推进
- 也可随时间衰减或撤销

`§8` 中的未闭合预测、继续条件与 open-state 要求，已由 [2026-04-22-vpc-time-and-error-contract-design.md](./2026-04-22-vpc-time-and-error-contract-design.md) 进一步冻结成可实现合同。

## 9. 当前已确认但待继续细化的合同

截至本版，以下内容已完成原则冻结，但尚需继续细化成更严格的实现合同：

1. `时间与误差合同`
2. `Predictor 合同`
3. `Precision 合同`
4. `最小闭环定义`
5. `VPC 理论能力质量检测`
6. `后续实际能力验证口径`

其中下一优先级最高的话题是：

`时间与误差合同`

因为一旦跨尺度像素已经成立，就必须明确：

- 每个 predictor 如何声明自己的预测粒度
- 不同粒度的 err 如何定义
- 同域、同时间参照如何成立
- 长远预测如何与短期预测共存而不互相污染

本优先话题已在 [2026-04-22-vpc-time-and-error-contract-design.md](./2026-04-22-vpc-time-and-error-contract-design.md) 中作为正式子 spec 收口；后续剩余工作转为实现合同测试与最小 substrate 落地。
