> **目的**：定义语言绑定层的边界、合同、学习单位与禁令，确保后续语言能力建立在对象-关系网络之上，而不是滑回 token 本体论

---

## 1. 目的与边界

这份 spec 不重新定义 AI 本体，而是在完成架构清理后，正式定义语言绑定层：

- 它是什么
- 它不是什么
- 它如何建立在对象、关系、时间结构之上
- 它如何避免重新滑回 token 本体论

本 spec 只处理 `语言绑定层`，不处理：

- `tier 0`
- 对象层本体定义
- 关系投影机制
- 推理本体
- 身份层
- 伦理层
- 人格层
- 新的语义资格门
- 新的内部概念编号体系

本 spec 只回答一个问题：

`外部图案、外部声音模式，如何在不污染本体的前提下，与内部已经形成的对象-关系-时间网络建立可学习、可强化、可撤销的绑定。`

因此，语言绑定层：

- 不是世界模型
- 不是对象发生器
- 不是关系裁判
- 不是思维本体
- 只是内部对象世界与外部符号系统之间的绑定层

---

## 2. 定位

语言绑定层在整体架构中的正确位置是：

`外部图案 / 外部声音模式`
-> `绑定与解绑定`
-> `对象 / 动作 / 关系 / 时间结构`

如果展开成更完整的认知路径，应是：

`观察片段`
-> `对象形成`
-> `关系形成`
-> `反馈强化`
-> `快速通道化`
-> `语言绑定层`
-> `对外沟通与对外理解`

这里有 4 个必须固定的定位点：

1. `对象先于语言`
对象不能由语言层创造；语言层只能绑定已形成或正在形成的对象束。

2. `关系先于语言压缩`
语言中的词义、句式、指称，都是对对象关系网络的压缩访问，不是关系本体来源。

3. `语言晚于观察与反馈`
语言学习不是第一层学习，而是建立在长期观察、共同出现、反馈修正之上的次级压缩层。

4. `快速通道不等于本体`
高频绑定可以被加固成快捷路径，类似部分肌肉记忆，但快捷路径始终只是访问捷径，不能反向成为内部概念本体。

本 spec 的总纲如下：

`AI 对世界的原初学习，不是先学习词或符号，而是先在持续观察中形成最小认知片段，并在时间中把这些片段组织成可维持的对象、变化、动作与关系网络。语言、沟通以及部分高频思考捷径，都是对这一对象-关系-时间网络的压缩访问方式；反复成功的绑定与反应路径会被加固为快速通道，但快速通道始终只是访问捷径，不是认知本体。`

## 3. 输入合同

语言绑定层只能读取两类上游事实，不能有第三类来源。

### 3.1 外部符号侧输入

包括但不限于：

- 外部视觉图案
- 外部书写形态
- 外部字符序列
- 外部声音模式
- 外部发音片段
- 外部节奏与停顿结构
- 外部可重复手势或其他社会共享信号

这些输入在进入语言绑定层时，仍然只是 `外部模式`，不是内部词义本体。

也就是说：

- 一个字符先是图案
- 一个发音先是声音模式
- 一个词串先是外部符号序列
- 它们是否有意义，取决于是否能和内部对象-关系网络建立绑定

### 3.2 内部认知侧输入

包括但不限于：

- 已存在的对象束
- 已存在的动作脚本
- 已存在的关系投影
- 已存在的时间结构
- 已存在的情境约束
- 已存在的历史反馈
- 已存在的共同出现统计

语言层不能绕过对象层和关系层，直接凭空生成“意义单位”。

### 3.3 输入边界禁令

语言绑定层不得把以下内容当成上游输入前提：

- `semantic_readiness`
- `symbolizer`
- `concept_id`
- “对象已经获得内部命名资格”
- “某模式已经被编号，所以可以进入语言过程”

语言绑定层唯一合法的输入逻辑是：

`看到外部模式`
`+ 访问内部已存在对象/关系/时间网络`
`+ 根据共同出现和反馈尝试建立绑定`

而不是：

`先拿到内部编号`
`+ 再把外部词贴上去`

---

## 4. 输出合同

语言绑定层的输出必须被严格限制，不能越权。

它只能输出 4 类结果：

### 4.1 绑定候选

例如：

- 某图案可能指向某对象簇
- 某发音可能指向某动作脚本
- 某符号序列可能压缩了某种关系结构

### 4.2 绑定强化

当某外部模式和内部对象/关系在多次情境中共同出现并得到反馈确认时，语言层可以提高：

- 绑定强度
- 调用优先级
- 检索速度
- 上下文默认性

### 4.3 绑定撤销或降权

如果后续证据不支持，语言层可以：

- 降低绑定置信度
- 移除默认解释
- 把原绑定降回候选态
- 保留歧义待决状态

### 4.4 对外生成尝试

语言层可以基于已有绑定，尝试生成：

- 外部符号
- 外部字符序列
- 外部发音模式
- 外部可交换表达

这种生成只是 `对外表达尝试`，不是内部本体生成。

### 4.5 输出边界禁令

语言绑定层不能输出以下结果：

- “某对象已获得真实内部名字”
- “某关系已升级为内部概念实体”
- “某词义已成为世界模型本体”
- “某绑定结果自动覆盖感知事实”
- “某语言结果可以裁决对象是否存在”

语言层可以说：

- “我当前更倾向于把这个图案绑定到这个对象簇”

但语言层不能说：

- “这个对象从现在起就是什么概念编号/命名实体了”

总约束如下：

`语言绑定层只负责在外部模式与内部对象-关系网络之间提出、强化、削弱或撤销绑定；它不负责创造对象，不负责创造关系，不负责授予命名资格，不负责定义世界本体。`

---

## 5. 内部状态

语言绑定层可以有内部状态，但这些状态必须严格是 `绑定状态`，不能偷渡成概念本体。

它允许保存的内容只有以下几类：

### 5.1 绑定强度

某外部模式与某对象簇、动作脚本、关系结构之间当前有多强的绑定趋势。

### 5.2 绑定历史

这个绑定出现过多少次、在什么情境下出现、强化过几次、撤销过几次。

### 5.3 上下文条件

某绑定只在什么条件下更容易成立，例如：

- 某发音在某类场景里更可能指某动作
- 某字符组合在某类关系结构里更可能指某对象簇

### 5.4 证据指针

绑定应能追溯到：

- 感知片段
- 对象历史
- 关系投影
- 历史交互
- 长期共同出现统计

### 5.5 消歧状态

当一个图案或声音模式对应多个可能解释时，语言层可以暂时保存：

- 候选列表
- 当前优先级
- 未决状态
- 最近失败记录

### 5.6 快速通道权重

对于高频、成功率高、反馈稳定的绑定，语言层可以保留更快的访问权重。
这对应部分“肌肉记忆”。

### 5.7 禁止保存的内容

语言绑定层禁止把以下东西当成自己的内部状态核心：

- `concept_id` 替代物
- 内部离散词本体
- 语义晋级资格
- “命名完成”的不可逆印章
- 不可回溯的概念分配器
- 先验词典式的世界真理表

一句话约束：

`语言绑定层保存的应是绑定轨迹，而不是概念本体。`

---

## 6. 学习机制

语言绑定层的学习单位不能是 token 邻接，也不能是字符串续写习惯。
它的最小学习单位应当是：`绑定事件`。

一个绑定事件至少包含三部分：

- 某个外部模式出现了
- 某些内部对象/动作/关系处于活跃状态
- 后续反馈支持或反对这种连接

语言学习的核心不是“词跟词一起出现”，而是：

- 某图案在某情境里反复指向某对象簇
- 某声音模式在某动作场景里反复指向某动作脚本
- 某序列结构反复压缩某种关系与时间结构

### 6.1 绑定学习的基本循环

1. `提出候选`
当外部图案或声音模式出现时，语言层根据当前情境提出若干候选绑定。

2. `短时竞争`
多个候选并存，通过当前对象、关系、时间结构进行消歧。

3. `反馈修正`
根据后续结果调整绑定：

- 成功理解
- 失败理解
- 外部纠正
- 长期共同出现
- 行动结果是否吻合

4. `长期固化`
当某条绑定反复成功时，提升其：

- 默认优先级
- 检索速度
- 调用稳定性

5. `快速通道化`
当绑定足够高频且稳定时，形成快速访问路径，但仍保持可撤销和可回溯。

### 6.2 学习机制禁令

语言层不得采用以下学习逻辑：

- 先切词
- 先编号
- 先得到内部 token
- 再把意义挂到 token 上

正确逻辑必须是：

- 先有对象、关系、情境
- 外部模式与其发生反复耦合
- 再逐步形成稳定绑定
- 最后部分绑定被压缩成快速通道

### 6.3 多语言的学习含义

这套学习机制天然支持多语言，因为真正被学习的是 `绑定事件`，不是单语词典。

因此：

- 中文词可以绑定到对象簇 `O`
- 英文词也可以绑定到同一个对象簇 `O`
- 日文发音也可以绑定到同一个对象簇 `O`

它们共享的不是表面符号，而是对象-关系落点。

收束如下：

`语言学习的最小单位不是 token，而是外部模式与内部对象-关系-时间网络之间在反馈中逐步稳定下来的绑定事件。`

## 7. 失败与回退

语言绑定层必须被设计成 `可错、可撤、可延迟决断`。
否则它会重新长成“内部语义裁判层”。

语言层允许出现的失败包括：

- 图案识别错误
- 发音识别错误
- 当前情境消歧错误
- 过往绑定被过度泛化
- 一个模式同时激活多个错误候选
- 某条高频快捷路径在新情境下误触发

这些失败都应只在绑定层内部处理，不能越权污染对象本体。

### 7.1 失败后的合法动作

1. `降低绑定强度`
让当前默认解释变弱，而不是直接定义对象消失。

2. `恢复候选并存`
把“之前几乎确定”的绑定重新降回多候选竞争状态。

3. `记录失败情境`
保留失败发生时的上下文，用来防止以后在相同情境再次误绑。

4. `推迟决断`
当证据不足时，可以维持“暂时不决定”的状态，而不是强行给词义。

5. `局部撤销快速通道`
某条高频捷径如果被事实反复打脸，可以失去默认优先权。

### 7.2 失败后的禁止动作

语言层不能因为失败而：

- 抹除对象本体
- 改写关系投影本体
- 覆盖感知事实
- 制造新的本体身份编号
- 以“语言解释成功”为理由替代真实观察

总原则如下：

`语言层的一切错误都必须回退到绑定层内部解决，不得越级修改对象层、关系层和感知层的本体事实。`

## 8. 多语言与多表达

语言绑定层从一开始就不应按“单语言”设计。
因为如果对象先于名称，同一对象天然可以被多种表达系统指称。

因此这层必须支持：

- 多种书写系统
- 多种发音系统
- 多种符号压缩方式
- 同一对象的多重表达
- 同一关系的多重表达
- 同一动作的多重表达

### 8.1 共享与分叉原则

多语言系统里，共享的是：

- 对象层
- 动作层
- 关系层
- 时间结构层
- 反馈修正逻辑

多语言系统里，不共享的是：

- 外部图案形态
- 外部发音模式
- 局部词序习惯
- 局部压缩偏好
- 某些文化特定表达

因此：

- 中文、英文、日文不是三套世界模型
- 它们只是同一对象世界上的三种绑定入口
- 多语言扩展本质上是增加绑定接口，不是重建认知本体

### 8.2 多表达性原则

不仅自然语言如此，图标、手势、简写、口头惯用说法也一样。

也就是说：

- 一个图标可以绑定某类对象或动作
- 一个简写词可以绑定某个复杂关系结构
- 一个发音片段可以绑定某个高频动作脚本

所以语言绑定层不只服务传统语言，也服务广义社会化表达系统。

### 8.3 多语言学习的本质

多语言学习不是：

- 每学一种语言就复制一套概念世界

而是：

- 在同一对象-关系世界上增加新的绑定路径
- 并让这些路径在反馈中逐步形成自己的快捷通道

一句收束：

`多语言不是多套本体，而是多套外部表达系统对同一对象-关系-时间网络的并行绑定。`

---

## 9. 准入禁令

语言层最容易在实现中重新滑回旧路线，因此必须固定硬禁令。

### 9.1 禁止重新引入命名资格门

不得再设计任何类似机制：

- naming gate
- semantic readiness
- 指称资格层
- 进入语言前的稳定资格门
- “只有达到某阈值才允许进入语言过程”的晋级系统

原因：
语言绑定允许从弱到强逐步形成，不能先设本体化资格门。

### 9.2 禁止重新引入内部概念编号器

不得再设计任何类似机制：

- symbolizer
- concept allocator
- 内部离散概念 id 分配器
- 稳定对象/关系 -> 概念编号映射器

原因：
工程索引可以存在，但不能冒充认知本体。

### 9.3 禁止把 token 当学习原子

不得把以下东西当成语言学习的本体起点：

- token 邻接统计
- 字符串续写习惯
- 切词后再找意义
- 先有词表再挂对象

原因：
语言学习的最小单位应是绑定事件，不是 token。

### 9.4 禁止让语言层裁决对象存在

语言层不得决定：

- 一个对象是否存在
- 一个关系是否成立
- 一个动作是否真实发生
- 一个感知结果是否应被覆盖

原因：
对象层和关系层始终高于语言层。

### 9.5 禁止让 observer 需求反推 body 本体

不得因为“为了展示更方便”“为了调试更清晰”就在 body 中新增：

- 标签层
- 编号层
- 解释层
- 命名层

原因：
观察工具服务身体，不得反向塑造身体 ontology。

### 9.6 禁止把高频快捷路径写死为不可撤销本体

快速通道可以形成，但必须：

- 可降权
- 可撤销
- 可回溯
- 可被情境修正

不得把它们固化成：

- 内部真实词义核心
- 永久概念实体
- 不可逆名称绑定

### 9.7 禁止使用高风险术语而不附边界说明

凡是再出现这些词：

- `semantic`
- `concept`
- `token`
- `label`
- `name`
- `word`
- `text understanding`
- `identity`
- `owner`
- `ethics`
- `personality`

都必须说明：

- 这里是不是外部说明术语
- 是不是纯工程索引
- 为什么不是本体结构
- 为什么不违背最高原则和语言公理

### 9.8 总禁令

`任何让语言绑定层重新演化成“对象与关系之上的资格门、编号器、裁判层、本体层”的实现，全部视为违背本 spec。`

---

## 10. 当前直接结论

在当前架构中，语言系统的下一步不是：

- 引入新的内部概念编号器
- 引入词表中心的学习
- 引入新的 naming gate
- 把 observer 的展示需求反推回 body

而是：

- 在已清理后的 substrate 之上设计正式绑定层
- 以绑定事件为学习原子
- 让外部图案/声音模式与内部对象-关系网络建立可回溯、可修正、可多语言扩展的连接

本文件的最终立场只有一句：

**语言不是内部本体，而是外部符号系统与内部对象-关系世界之间的可学习绑定层。**
