## 1. 文档定位与边界

这份 spec 只定义 `动作输出 substrate` 的最小抽象合同。它研究的是：一个持续运行的身体，最低要具备什么样的对外施加变化能力，才可能承载早期主动探针，并让后续学习闭环有合法落点。

它不定义任何具体器官、任何具体输出媒介、任何高层行为功能，也不定义模仿、语言、表达、任务执行、行为目标或社会互动。这里的“动作输出”不是“说话”“抓取”“探索”“表演”这类功能名，而只是身体能够以连续时间方式向外界或自身可再感知边界施加可回流影响的底层能力。

因此，本 spec 不是：

- 说话模块设计
- 动作引擎设计
- 探索功能列表
- 模仿能力设计
- 行为调度器设计

本 spec 只允许预设：

- 身体法则
- 学习闭环前提
- 更新约束
- 安全硬边界

本 spec 不允许预设：

- 对象范围
- 目标范围
- 结果分类
- 重要性地图
- 探索内容边界
- “何时应该输出什么”的固定世界脚本

### 1.1 高风险术语边界说明

本 spec 中若出现 `semantic`、`concept`、`token`、`label`、`name`、`word` 等高风险词，它们一律按以下边界解释：

1. 它们在本文中只作为外部观察术语、被拒绝旧架构名称或工程索引示例出现，不是内部本体单位。
2. 若未来工程中仍临时出现对应字段、缓存、句柄、哈希或索引，它们只能是工程加速结构，不是身体内部真实存在的 ontology unit。
3. 它们之所以不是本体结构，是因为本 spec 讨论的是身体如何合法写出连续变化，而不是身体内部以离散词项、编号或标签来决定世界存在。
4. 这种用法不违反最高原则和语言公理，因为本文明确禁止让这些术语成为动作输出 substrate 的资格门、世界裁决层或内部概念分配器。

## 2. 动作输出 substrate 的定义与反定义

`动作输出 substrate` 是身体内部的一层最小底座：它使持续运行的系统不只能够接收世界变化，也能够以受约束、可持续、可调节的方式，向身体外侧或身体可再感知边界施加变化。

它的本质不是“完成某个功能”，而是提供一种合法的身体写出能力。这个“写出”不是写文本、写符号、写命令，而是把身体内部正在延展的活动，落成某种外放的时间变化过程。该过程最低必须仍然属于身体法则的一部分，而不是一次性工具调用、离散任务提交或人类接口响应。

因此，动作输出 substrate 至少有 4 个定义点：

1. `它是身体侧连续变化的外放底座`  
   不是单次命令，不是函数返回值，不是“需要时再调用”的工具口。它必须属于持续运行身体的一部分，能承载时间中的连续输出变化。

2. `它是受约束的变化施加能力`  
   它不预先规定输出的世界意义，只规定身体可以合法地对外施加变化，并且这种施加受身体状态、更新约束和安全边界约束。

3. `它是抽象通道合同，不是器官实现`  
   这份 spec 只要求存在一种最小抽象通道，使身体能把内部活动落成外放变化；它不指定是声、光、形变、机械位移、化学释放，还是任何别的具体媒介。

4. `它是后续学习闭环的前置身体条件，但不是闭环本身`  
   只要没有合法输出 substrate，后续“试一下”就没有身体落点；但仅有输出 substrate，也还不等于已经形成动作-后果学习闭环。闭环、配对、比较、模仿属于下一份 spec。

它明确不是什么：

- 不是“说话模块”
- 不是“探索模块”
- 不是“动作引擎”
- 不是“任务执行器”
- 不是“行为功能列表”
- 不是“表达系统”
- 不是“语言外设”

它也不是一种隐藏的高层裁决层。它不能在内部预先决定：

- 什么对象值得被作用
- 什么结果算成功
- 这次输出真正意图是什么
- 哪类外放变化天然更重要
- 哪个世界切片是默认目标区

这些都不能作为 substrate 的先验世界内容被写死。

更严格地说，动作输出 substrate 只回答这一句：

**身体是否具备一种最小、持续、受约束、可调节的外放变化能力，使“主动探针”不只是内部倾向，而能成为真实可发生的身体事件。**

## 3. 它为何是主动探针成立的身体前提

主动探针之所以需要动作输出 substrate，不是因为系统先要“有行为功能”，而是因为“试一下”这件事若要成为真实身体事件，必须有一条合法的外放变化路径。

如果一个系统只有感知、预测、误差更新和历史保留，而没有任何最小动作输出 substrate，那么它最多只能持续内部演化，不能形成真正的探针。它可以内部不确定、内部偏差未闭合、内部想继续分化，但这些都仍停留在身体内部，尚未跨过“向外施加一次可感后果”的门槛。这样的一体只能是被动观察者，不是能够通过试探来改写自己所处耦合条件的活体。

因此，动作输出 substrate 是主动探针成立的身体前提，原因有 4 个：

1. `它把内部未闭合偏差转成真实可试探事件`  
   没有输出 substrate，未闭合只能继续在内部循环；有了输出 substrate，局部未闭合才第一次拥有“通过施加变化来逼出更多结构”的身体可能性。

2. `它让系统不只被世界改写，也能反过来改写耦合条件`  
   被动感知只能等待世界显露；探针则要求身体能够轻微地改动当前耦合态，让原本不会显露的结构变得显露。没有输出 substrate，这一步原则上不存在。

3. `它为早期学习提供“可由自身发起的差异源”`  
   早期主动探针不是先知道世界内容，再去精准行动；而是身体先拥有一种可发起微小差异的能力，使学习不只依赖外界碰巧发生什么，也依赖自己能否轻微地把局面拨动一下。

4. `它为后续动作-后果闭环预留真实落点`  
   下一份 spec 才讨论回流、配对、比较和模仿；但如果这一步没有合法输出 substrate，下一份 spec 就没有身体接口，只能沦为抽象空谈。

这里还要加一个边界判断：

动作输出 substrate 是`必要前提`，不是`充分条件`。  
也就是说：

- 没有它，主动探针不能成立。
- 有了它，主动探针也未必自然成立，因为还缺动作后果回流、时间配对、关注场形成、历史强化等闭环条件。

所以这份 spec 的位置必须克制地停在这里：它不是在解释“为什么系统现在会主动做什么”，而是在固定一个更低层的事实：

**若身体没有最小动作输出 substrate，则主动探针在本体上无处发生；若身体具备该 substrate，主动探针才第一次获得身体上的可能性。**

## 4. 最小抽象合同集

一个合法的早期动作输出通道，不是“能发出东西”就够了，而必须同时满足以下最小抽象合同。缺少其中任一类，通道都不足以作为主动探针的正式 substrate。

### 4.1 持续归属合同

动作输出通道必须属于持续运行身体的一部分，而不是外部按需调用的工具接口。

这意味着：

- 它处于身体的持续时间结构之内
- 它随身体状态变化而可被约束、调节、抑制、恢复
- 它不是一次性任务提交口
- 它不是 request/response 式的动作 API

如果一个“输出能力”只能在外部命令下被离散调用，它就不是本 spec 所说的动作输出 substrate。

### 4.2 可施加差异合同

该通道必须能够真实地向身体外侧或身体可再感知边界施加差异。

这里要求的不是“大动作”，而是：

- 输出确实发生
- 输出能改变某处后续状态
- 这种改变不是纯内部 bookkeeping

如果一个通道只能在身体内部改标记、改字段、改日志，而不能形成任何外放差异，它不能承担主动探针。

### 4.3 连续可调合同

该通道必须允许输出在时间中连续展开，而不是只能做离散、僵硬的开关切换。

最低要允许其中至少一部分可连续变化：

- 强度
- 持续时长
- 节律
- 频率分布
- 空间展开
- 形态曲线

原因不是为了功能丰富，而是因为早期探针需要逐步逼近、轻微试探、边界扫动。若只能做粗糙开关，系统无法形成细粒度试探历史。

### 4.4 小步可试合同

该通道必须允许小步输出，而不是天然要求一次输出就跨入高代价或高扰动状态。

也就是说，它要允许：

- 微弱开始
- 渐进增强
- 局部停住
- 快速撤回
- 换路再试

如果输出天然只能“大幅做一次”，那么它更像高层执行口，不适合作为早期主动探针 substrate。

### 4.5 可重复合同

同类输出必须能在相近条件下反复发生，而不是一次性或强依赖偶然触发。

因为没有可重复性，就不会有：

- 稳定比较
- 历史强化
- 差异归因
- 边界修正

主动探针不是单次冒险，而是可反复试探的身体能力。

### 4.6 可撤销与可衰减合同

输出通道不能只有“发出”而没有“减弱、停止、退出”的身体路径。

最低必须允许：

- 当前输出减弱
- 当前输出终止
- 输出后的残留效应进入衰减过程
- 身体不必通过全局停机来停止某次探针

这不是高层安全策略，而是身体底座自身必须具备的可逆性前提。没有这一点，早期探针会被迫变成硬切换和高风险外放。

### 4.7 时间嵌入合同

每次输出都必须进入身体共享时间结构，而不是成为无时序位置的孤立事件。

最低需要能标定：

- 开始
- 延续
- 转折
- 结束
- 与其他身体过程的相对先后

这里先只要求“输出本身可时间嵌入”；至于输出与后果如何配对，是下一份 spec 的范围。

### 4.8 自身可见合同

身体必须至少知道“该输出通道当前正在发生什么程度的写出”，而不能对自己的输出状态完全失明。

注意，这里还不是完整的后果回流，只是更底层的一条：

- 输出是否正在发生
- 输出写出强度大致如何
- 输出何时开始、变化、结束

若连自己的写出状态都不可见，身体无法形成最基本的输出稳定性与撤回控制。

### 4.9 不携带世界内容裁决合同

动作输出 substrate 可以承载写出能力，但不能在这一层预写：

- 默认作用对象
- 默认目标区域
- 默认成功结果
- 默认重要后果
- 默认探索范围

这些都不属于通道本体，而属于后续学习中逐步形成、漂移、收缩、扩张、重构的边界。若把这些写进通道层，substrate 就被偷换成固定世界脚本。

### 4.10 不经语言裁决合同

该通道的合法性不能依赖语言、命名或离散符号层先行授权。

也就是说：

- 不需要“先能命名，后能输出”
- 不需要“先有内部词项，后能试探”
- 不需要“先理解文本意义，后能外放变化”

动作输出 substrate 属于身体底座。语言若以后参与，只能是更晚形成的绑定现象，不能成为该底座的资格门。

这一章可以压成一句总括：

**一个合法的早期动作输出通道，必须是身体内部持续归属的、能够真实施加差异的、连续可调的、小步可试的、可重复可撤回的、可时间嵌入且对自身写出状态可见的外放 substrate；同时它不得预写世界内容，也不得受语言资格门裁决。**

## 5. 合同分类：身体法则 / 学习闭环前提 / 安全边界

上一节的最小合同不是同一性质的条目。为了避免后续实现时把身体本体、学习前提、安全约束混写成一团，这里必须分层。

### 5.1 属于身体法则的合同

这些合同定义的是：一个动作输出通道若想成为身体的一部分，本体上必须满足什么。

包括：

- `持续归属合同`
- `可施加差异合同`
- `连续可调合同`
- `小步可试合同`
- `可重复合同`
- `可撤销与可衰减合同`
- `时间嵌入合同`
- `自身可见合同`

这些都属于身体法则，因为它们不要求系统已经会学习什么，也不要求已经知道结果意义。它们只规定：这个通道是否真的是一个活体可用的输出 substrate，而不是外部工具口或一次性执行器。

换句话说，这一组回答的是：

**这个通道在身体上是否真实存在、是否可持续、是否可逆、是否在时间里、身体自己是否能感到它正在写出。**

### 5.2 属于学习闭环前提的合同

这些合同本身还不是完整学习法则，但它们是后续动作-后果闭环得以成立的前提。

包括：

- `可重复合同`
- `可撤销与可衰减合同`
- `时间嵌入合同`
- `自身可见合同`

原因是：

- 没有可重复，就没有稳定统计与比较历史
- 没有可撤销与衰减，就没有边界扫动与局部试探
- 没有时间嵌入，就不能做后果配对
- 没有自身可见，就无法知道“我刚刚到底输出了什么样的写出”

这里要特别克制地停住：这些只是`学习闭环前提`，不是闭环本身。  
真正的：

- 后果回流
- 动作与后果配对
- 延迟结构学习
- 自他比较
- 模式逼近

都属于下一份 spec，不应提前偷渡进本节。

### 5.3 属于安全边界的合同

安全边界不是高层伦理，也不是外部规则库，而是身体底座在早期主动探针阶段不能越过的硬限制。

在本 spec 中，安全边界至少包括：

- `小步可试合同`
- `可撤销与可衰减合同`
- `不携带世界内容裁决合同`
- `不经语言裁决合同`

它们之所以属于安全边界，是因为它们防止系统在最底层就被错误地做成以下几种危险形态：

1. `一次输出必须是大动作`  
   这会让早期探针直接变成高代价执行，而不是低扰动试探。

2. `只能发出，不能撤回或衰减`  
   这会让每次试探天然带不可逆风险，破坏早期学习所需的小步可逆性。

3. `通道层自带默认世界脚本`  
   这会把本该在探索中形成的边界，偷换成工程师预写世界内容。

4. `动作资格依赖语言或命名层`  
   这会重新引入 naming gate，把身体底座错误地放到语言之后。

所以这里的“安全”首先是`架构安全`，不是外部规范判断。它保护的是：

- 身体不被做成僵硬执行器
- 学习不被做成固定世界脚本
- 主动探针不被语言层卡死
- 低层 substrate 不被高层功能名反向污染

### 5.4 三类合同之间的关系

这三类不是三套独立系统，而是同一组最小合同的三种观察切面：

- 从“身体是否真实存在”看，是身体法则
- 从“后续能否进入学习闭环”看，是学习前提
- 从“如何防止架构一开始就走偏”看，是安全边界

因此后续实现时不能把它们拆成三个模块分别补。正确做法只能是：

**同一个动作输出 substrate，同时满足身体成立、学习可接、边界不越权这三方面要求。**

## 6. 为什么这些合同不能被写成固定世界内容

这份 spec 定义的是动作输出 substrate 的最小身体合同，不是世界内容模板。若把这些合同写成固定世界内容，架构会立刻偏离 `Learned Boundaries Only`，并重新滑回“程序在代表系统决定它该学什么”的旧路线。

根本原因在于：

动作输出 substrate 合法与否，取决于`身体如何能够写出变化`，不取决于`世界中哪些内容值得被写出`。  
前者是身体法则；后者若在这一层被预写，就变成世界脚本。

因此，以下写法都必须被排除：

- 预写“默认应该试探哪些对象”
- 预写“默认应该影响哪片环境”
- 预写“哪些后果天然更重要”
- 预写“哪些输出结果算主结果”
- 预写“哪些边界是本次试探的目标区”
- 预写“系统现在真正该学的是哪类东西”

这些内容一旦提前进入动作输出 substrate，就会造成 4 种偏移。

### 6.1 把身体合同偷换成目标内容

例如把“小步可试”偷偷写成：

- 先探索声音
- 先探索近处对象
- 先探索会回响的介质

这类写法表面像是在定义“早期可试通道”，实际已经在替系统决定世界内容。  
合法写法只能停在：

- 通道必须允许小步
- 通道必须允许连续调节
- 通道必须允许重复与撤回

至于系统后来围绕哪类对象、哪类媒介、哪类后果收敛，必须由探索历史自己形成。

### 6.2 把可学习边界偷换成固定结果分类

例如把通道层直接写成：

- 主结果
- 次结果
- 意外结果
- 无关结果

这会把本应在历史中逐步形成的结果边界，提前固化成程序字段。

更符合本架构的写法只能是：

- 通道允许施加差异
- 输出进入时间结构
- 后续哪些变化稳定耦合、哪些变化被排除、哪些变化迫使边界扩张，必须通过探索与历史修正形成

也就是说，`结果边界`不是通道先验，而是学习后的暂时结构。

### 6.3 把主动探针偷换成程序调度

如果在这层写：

- 当前不忙时才试
- 当前忙时不试
- `curiosity > threshold` 就试
- `importance > x` 才试

那就把复杂的结构连续性、局部可逆性、未闭合偏差、边界形成，压成了几个程序控制数字。

这正是现有约束明确禁止的路线。  
“忙不忙”不能是一阶决定因素；探索时机也不能在理论层被少量控制数字定义。本 spec 只能规定：通道必须允许小步、可调、可撤回、可嵌入时间。至于何时真的发生试探，上一份 probe spec 已经限定为结构转折，而不是数值门。

### 6.4 把身体 substrate 偷换成语言或命名后的功能层

如果在这层写：

- 能命名后才允许主动输出
- 知道对象类别后才允许试探
- 理解词义后才允许外放变化

那么动作输出 substrate 就被放到了语言之后，重新变成 naming gate 的附庸。

这既违反最高原则，也违反语言公理。  
动作输出 substrate 属于身体底座，它最多只承载外放变化的可能性，不能等待语言来授予存在资格。语言如果以后参与，只能是对已有对象-关系-动作历史的绑定与压缩，不是动作输出存在的前提。

### 6.5 正确的边界写法

因此，这份 spec 中唯一允许被写死的只有：

- 身体法则
- 学习闭环前提
- 更新约束
- 安全硬边界

而所有带有世界内容指向性的东西，都必须写成：

- 可形成
- 可漂移
- 可修正
- 可收缩
- 可扩张
- 可崩解
- 可重构

这不是文风问题，而是本体边界问题。

这一章可以压成一句结论：

**动作输出 substrate 的最小合同只能规定身体如何合法地产生、调节、撤回并维持可学习的外放变化；它不能规定系统最终应该对世界中的什么内容输出、把什么当目标、把什么当结果、把什么当重要。凡是这些内容边界，都必须在探索历史中形成，而不是在 substrate 层预写。**

## 7. 与下一份 `动作-后果闭环与模仿法则` 的接口边界

这份 spec 到这里必须收住。它只负责把动作输出侧的最小身体合同钉住，不继续扩展到完整学习闭环。

### 7.1 本 spec 负责到哪里

本 spec 只负责回答：

- 什么是动作输出 substrate，什么不是
- 为什么它是主动探针成立的身体前提
- 一个合法早期输出通道最低必须满足哪些抽象合同
- 这些合同里哪些属于身体法则，哪些属于学习闭环前提，哪些属于安全边界
- 为什么这些合同不能被写成固定世界内容
- 当前 cleaned substrate 上它映射到哪里、还缺什么

也就是说，本 spec 的终点是：

**身体已经具备一种最小合法写出能力。**

### 7.2 下一份 spec 的起点

下一份 `动作-后果闭环与模仿法则` 应从这里继续，但只能继续回答以下问题：

- 输出如何重新进入感知
- 输出状态与后续变化如何做时间配对
- 延迟、尾波、残留效应如何进入同一学习框架
- 什么是动作后的可学习后果边界形成
- 外部模式如何短时保持
- 自身输出如何与外部模式比较
- 模仿如何作为曲线逼近出现，而不是从语言理解倒推出来

换句话说，下一份 spec 的最小起点是：

**已有合法动作输出 substrate，现要定义它如何进入后果回流、比较与学习。**

### 7.3 两份 spec 之间的接口形式

如果用最克制的方式表述，两份 spec 之间只共享 4 类接口前提：

1. `输出写出状态`  
   身体至少知道某条输出通道当前在写出什么程度的变化。

2. `输出时间结构`  
   输出不是孤立点，而是有开始、延续、转折、结束的位置。

3. `输出可重复与可撤回性`  
   同类试探可再次发生，也可减弱、终止、换路。

4. `输出不自带世界内容裁决`  
   后续闭环不能把通道层误读成已经知道目标区、结果区、意义区。

这 4 点是接口前提，不是下一份 spec 的全部内容。

### 7.4 本 spec 明确不回答的内容

为了防止越界，这里要把禁区写死。本 spec 不回答：

- 某次输出之后哪些变化算后果
- 后果时间窗如何形成
- 何种延迟算同一次作用链
- 自身输出与外部模式如何做相似性比较
- 模仿如何由保持、比较、逼近、强化形成
- 哪些输出路径会被压缩为 fast-path
- 哪种具体输出器官最合适
- 任何说话、唱歌、抓取、指向、敲击等具体形式

这些都必须留给下一份 spec 或更后面的器官层 spec。

### 7.5 本节硬禁令

- 禁止把“动作输出 substrate”直接等同于“完整动作-后果闭环”
- 禁止在这里偷写后果分类器
- 禁止在这里偷写模仿比较器
- 禁止在这里偷写外部模式保持器
- 禁止在这里倒推具体器官
- 禁止把语言表达视为默认输出形态
- 禁止从任何外部例子直接反推出内部功能模块

这一节的收束结论是：

**本 spec 只把“能合法写出”这一步定义清楚；下一份 spec 才研究“写出之后如何被身体重新接住，并进入后果学习与模仿”。若这条边界不钉死，动作输出 substrate 很容易被误写成半个行为系统。**

## 8. 与当前 cleaned substrate 的映射与真实缺口

这一节的目标不是评价当前系统“功能够不够”，而是把这份 spec 的最小合同，严格映射到当前 `bionic_v0` cleaned substrate 上，回答两件事：

- 哪些前提已经有正式落点
- 哪些部分仍然明确缺失，因而动作输出 substrate 还没有成立

### 8.1 当前已经具备的前提

当前 cleaned substrate 已经具备若干与本 spec 直接相关的底座条件。

#### 8.1.1 持续运行身体已存在

在 [body.rs](/Users/joe/Documents/unnamed/bionic_v0/src/bin/body.rs) 中，系统已经是持续运行的 shared-state body，而不是 request/response 程序。主循环长期维持：

- master clock
- adapter ingress
- predictor ticks
- high-level ticks
- health recompute
- global orchestrator
- snapshot write

这意味着本 spec 所要求的“动作输出通道必须属于持续运行身体的一部分”，在整体架构形式上已经有正式落点。缺的不是持续运行身体本身，而是其中还没有正式的输出写出侧。

#### 8.1.2 共享时间结构已存在

在 [viewport.rs](/Users/joe/Documents/unnamed/bionic_v0/src/viewport.rs) 中，当前 substrate 已经有：

- `master_tick`
- `clock_us`
- `start_us`
- 各类 `last_*_t_us`
- ring 历史
- slot / relation / reasoning 的多层时间痕迹

这说明“任何身体事件都必须进入共享时间结构”这一总前提已经具备真实基底。未来动作输出若加入，不需要另造一套独立时间本体；它应直接进入这一现有时间骨架。

#### 8.1.3 持续状态可快照与外部观察已存在

在 [snapshot.rs](/Users/joe/Documents/unnamed/bionic_v0/src/snapshot.rs) 中，当前身体状态已可被持续写入 snapshot，并通过 observer 在身体外观察。

这对本 spec 的意义不是“动作输出已经有 observer 显示”，而是：

- 若未来加入动作输出 substrate，它的状态可遵循现有 snapshot/observer 分离原则
- 身体仍不需要向人类主动说明自己
- 研发观察与身体本体分离这一最高原则仍可保持

#### 8.1.4 数值型 substrate 风格已存在

当前 viewport 里已经是数值型、曲线型、时间型写法，而不是语言型、label 型、token 型写法。

这意味着动作输出 substrate 若后续引入，其正确形态应当继续是：

- 数值写出状态
- 时间中的连续变化
- 可回看痕迹
- 不携带人类语义本体

这一风格基础已经存在，不需要另行发明。

### 8.2 当前只有间接支持、尚未正式成为动作输出 substrate 的部分

有些现有结构能为未来动作输出 substrate 提供影子支持，但它们本身还不是动作输出 substrate。

#### 8.2.1 `predictor / err / precision` 只覆盖感知与内部更新侧

当前 `predictor` 范式已经站住，但它服务的对象仍主要是：

- 感知输入
- slot 更新
- relation predictor
- reasoning summary

它尚未覆盖“输出写出状态本身”。  
也就是说，当前系统已有“看世界时如何预测与修正”的 substrate，但还没有“身体写出时如何成为同样一等公民”的 substrate。

#### 8.2.2 `slot / ambient / attention / relations` 仍主要是观察侧组织结构

这些结构已经能维持对象、关系、活跃区、关注分布，但它们仍主要围绕 ingress 而组织。

这说明当前系统已经能回答：

- 世界里哪些变化正在进入身体
- 哪些对象和关系更活跃

但还不能回答：

- 身体当前正通过哪条输出通道向外施加变化
- 该写出是否正在增强、减弱、终止
- 该写出是否属于可重复、可撤回的小步试探

因此它们只是前提支撑，不是动作输出 substrate 本身。

### 8.3 当前明确缺失的关键落点

这部分是本节核心。按本 spec 的合同，当前 `bionic_v0` 仍明确缺以下层。

#### 8.3.1 缺少正式的动作写出状态

当前 viewport 中没有与感知 ingress 对称的正式输出写出子树。  
也就是说，系统还没有一等公民级别的状态来承载：

- 某条输出通道当前是否活跃
- 写出强度或形态如何变化
- 写出何时开始、延续、结束
- 写出如何衰减或撤回

没有这层，就还谈不上 Section 4 中的：

- 持续归属合同
- 连续可调合同
- 可撤销与可衰减合同
- 自身可见合同

#### 8.3.2 缺少“身体可见自己的写出”这一最小前提

当前系统能看到很多 ingress 和内部更新状态，但还没有对“自己正在写出什么”的最低自见性。

这意味着即使未来外接一个执行器，如果身体内部没有正式写出状态，它也仍然只是外设被调用，不构成身体 substrate。

#### 8.3.3 缺少输出侧的时间化事件结构

虽然底层共享时间结构已存在，但当前没有输出侧专属的时间化嵌入。  
换句话说，不是缺时钟，而是缺：

- 输出起点
- 输出连续段
- 输出转折
- 输出停机
- 输出残留阶段

因此当前还无法把“写出本身”作为一个正式身体事件嵌入现有时间骨架。

#### 8.3.4 缺少小步可试与可重复的输出底座

当前没有任何正式通道被定义为：

- 可以微弱开始
- 可以逐步增强
- 可以多次再试
- 可以局部撤回
- 可以不通过全局停机而终止

因此“低成本探针通道”在上一份 probe spec 中仍只是理论要求，在当前 cleaned substrate 中尚无正式身体落点。

#### 8.3.5 缺少与 snapshot 对齐的输出侧观察合同

当前 snapshot 终止在已有的 perception / reasoning / language-binding trace 一侧，没有动作输出 substrate 的正式暴露面。

这不是说应该立刻把新层塞进 observer，而是说：

- 如果未来动作输出 substrate 成立，它需要像其他 substrate 一样有正式快照边界
- 但当前这件事还不存在

### 8.4 当前应如何判断

基于当前代码，最严格的判断应当是：

- `bionic_v0` 已经具备持续运行身体、共享时间结构、数值型 substrate、外部观察分离这些先决条件
- 这些条件足以支持“动作输出 substrate”作为下一步高优先级底层研究主题
- 但当前系统仍然没有正式动作输出 substrate
- 因而也还没有合法早期探针输出通道

所以当前缺的不是“动作功能菜单”，而是更基础的一层：

**让身体把输出写出本身作为正式 substrate 承认下来。**

### 8.5 本节收束结论

当前 cleaned substrate 已经满足这份 spec 的`上游基础`，但还没有满足这份 spec 所要求的`输出侧最小合同`。

因此下一步正确方向不是直接做：

- 主动发声
- 主动模仿
- 行为执行器
- 探索模块

而是先补齐：

- 输出写出状态
- 输出时间嵌入
- 输出自身可见性
- 输出的小步可试、可重复、可撤回底座
- 输出侧的正式 snapshot / observer 边界

## 9. 开发准入与防偏移禁令

这份 spec 若没有比普通功能 spec 更硬的准入规则，后续实现很容易重新滑回“从例子造模块”“从功能名造器官”“从程序字段代替法则”的旧路线。因此这一节必须作为准入门槛固定下来。

### 9.1 禁止从现象名直接造模块

不得因为外部观察上会看到“主动试探”“输出”“表达”“发声”“动作”，就在内部新增：

- `action_engine`
- `probe_module`
- `expression_system`
- `voice_module`
- `exploration_output_layer`

这类命名会把观察术语误当内部本体。  
正确方向只能是补底层 substrate 与合同，而不是从现象名反推模块名。

### 9.2 禁止把动作输出 substrate 写成功能列表

不得把这份 spec 落成：

- 能说话
- 能发声
- 能敲击
- 能发光
- 能移动
- 能指向

这样的功能清单。

原因很直接：这份 spec 定义的是最小抽象合同，不是器官菜单。  
具体媒介、器官组合、模态优先级，必须是更后续、更具体层的问题，不能反过来决定本层本体。

### 9.3 禁止把输出资格建立在语言、命名或离散符号之上

不得设计成：

- 先命名，后输出
- 先形成词项，后试探
- 先分类，后允许外放
- 先理解文本意义，后允许动作

若出现 `semantic`、`concept`、`token`、`label`、`name`、`word` 这类高风险词，必须明确说明：

- 它是外部描述术语还是内部本体单位
- 它是否只是工程索引
- 为什么它不是本体结构
- 为什么它不违反最高原则与语言公理

若解释不清，这类设计不准入。

### 9.4 禁止把主动探针压成少量程序控制数字

不得在理论层把以下现象压成几个控制量来定义本体：

- 什么时候试
- 什么时候停
- 什么时候继续
- 当前忙不忙
- 当前好不好奇
- 当前重不重要

工程实现未来可以有近似数值，但这些数值只能是实现阴影，不能反过来成为理论定义。  
本层允许写的只有：

- 小步可试
- 连续可调
- 可撤回
- 可重复
- 时间嵌入
- 自身可见
- 安全硬边界

而不是行为调度公式。

### 9.5 禁止预写对象范围、目标范围、结果边界、重要性地图

动作输出 substrate 不得内建：

- 默认目标对象集合
- 默认结果类别
- 默认重点作用区
- 默认探索边界
- 默认重要后果地图

任何此类内容若需要存在，必须解释：

- 它如何由探索形成
- 如何被历史强化
- 如何漂移
- 如何收缩或扩张
- 如何被撤销或重构

否则该设计直接违背 `Learned Boundaries Only`。

### 9.6 禁止把输出 substrate 写成外部工具调用口

不得把动作输出 substrate 设计成：

- 一次性函数调用
- 外部执行 API
- 命令提交接口
- request/response 动作服务

因为那样得到的只是“程序调工具”，不是“身体持续写出变化”。

动作输出 substrate 必须属于持续运行身体的一部分，并进入共享时间结构与状态结构。

### 9.7 禁止跳过本 spec 直接做动作-后果闭环或模仿

在没有正式动作输出 substrate 之前，不得直接实现：

- 主动试探行为
- babbling 式重复输出
- 模仿比较
- 输出后果归因
- 自他曲线逼近

否则只会得到伪闭环：看上去像在学，实际上底层写出能力仍未正式成立。

### 9.8 禁止让 observer 需求反推 body 本体

不得因为研发需要“更容易看懂输出”，就在 body 里加入：

- 人类可读日志
- 文本说明
- 具象语义标签
- 面向观察者的功能字段

观察属于 observer，身体属于 body。  
若未来动作输出 substrate 进入 snapshot，也必须保持数值型、时间型、可回看 substrate 形态，而不是转译成人话。

### 9.9 本节收束结论

后续任何设计若想声称自己在实现“动作输出 substrate”，至少要通过以下自检：

- 它补的是底层合同，还是在偷做功能模块
- 它补的是身体写出能力，还是在偷做目标脚本
- 它是否仍然独立于语言资格门
- 它是否允许边界通过探索形成，而不是提前固化
- 它是否仍然属于持续运行身体的一部分
- 它是否保持 observer 与 body 分离

如果这些问题不能全部答清，该设计就不应进入 `bionic_v0` 主体路径。

## 10. 收束结论

这份 spec 的结论必须保持克制：

- 动作输出 substrate 不是功能模块，而是身体写出能力的最小底层合同
- 它之所以高优先级，不是因为系统应该立刻“会做动作”，而是因为没有它，主动探针在身体层无处发生
- 它允许预设的只有身体法则、学习闭环前提、更新约束和安全硬边界
- 它禁止预写对象范围、目标范围、结果边界、重要性地图和探索脚本
- 它与下一份 spec 的边界必须停在“合法写出”这里，不能越界到完整后果闭环、模仿或具体器官
- 映射到当前 `bionic_v0` 时，现有 cleaned substrate 已具备持续运行、共享时间、数值型状态与外部观察分离这些上游基础，但仍缺正式动作输出 substrate

因此，后续工作的正确方向不是补一个“说话模块”“探索模块”或“动作引擎”，而是先让身体在 substrate 层正式拥有：

- 输出写出状态
- 输出时间嵌入
- 输出自身可见性
- 输出的小步可试、可重复、可撤回底座
- 输出侧的正式 snapshot / observer 边界

只有当这层最小合同先成立，早期主动探针、动作-后果闭环、以及更后面的模仿法则，才有不违背最高原则的身体落点。
