# Emergent-Function Life Principle Design

Status: FROZEN CANDIDATE for theory alignment on 2026-05-20.

Chinese proposal:

```text
把多种功能作为一种系统的涌现现象来设计。
```

## Purpose

This document promotes the user's proposal into a top-level life-design
principle:

```text
Functions are emergent observer-side patterns of one integrated living
substrate, not isolated body-side feature modules.
```

The purpose is to prevent future work from building a menu of independent
features and then calling that menu "life". A living system may show many
abilities from the outside, but those abilities must arise from one continuous
substrate: shared coordinates, shared viewport, pressure, prediction error,
precision flow, action write-out, consequence return, residue, re-entry, and
bounded learning.

## Boundary

The highest principle remains unchanged: the system is a silicon-life
substrate, not a request/response program. Research observation and human
design descriptions stay outside the body.

`function`, `feature`, `capability`, `ability`, `organ`, `module`, `system`,
`scheduler`, `controller`, `language`, `life`, and `body` are external design
descriptions in this document. They are not internal ontology units and do not
authorize body-side feature identities.

High-risk terms are bounded as follows:

- `semantic`, `concept`, `token`, `label`, `name`, `word`,
  `text understanding`, `identity`, `owner`, `ethics`, and `personality` may
  appear only as rejected drift shapes or external review terms.
- Engineering file names, Rust module names, indices, ids, structs, and report
  fields are implementation handles. They are not proof that the body contains
  a matching ontology unit.
- Observer reports may describe an emergent function, but the body must remain
  numeric, temporal, curve-based, and observer-separated.

## Core Position

The correct design direction is:

```text
one living substrate
-> recurring cross-scale dynamics
-> observer-recognizable functional pattern
```

The rejected direction is:

```text
many programmer-written feature modules
-> externally composed behavior menu
-> called life afterward
```

A function is admissible only when it can be traced back to substrate dynamics
that would continue to exist without the observer's function word.

Examples:

- "initiative" is unresolved pressure, precision reallocation, probe law, and
  legal write-out becoming a visible active pattern.
- "expression" is internal pressure flowing through surface, vocal, action, or
  byte output substrates under boundary regulation.
- "learning" is consequence return, curve correction, residue, sedimentation,
  and re-entry, not a separate learning app.
- "stability" is support, reserve, route recovery, suppression, and recovery
  debt, not a mood or control panel.
- "language" is binding and de-binding between external patterns and existing
  object-relation-time structures, not a token brain.
- "responsible-person recognition" is an innate imprinting-like bias plus
  long-term familiarity sedimentation and hard-to-switch attachment pressure,
  not a late legal label and not an owner identity ontology.

The deferred "brain police" name is bounded by
[2026-05-21-internalized-social-inhibition-bias-lock-design.md](./2026-05-21-internalized-social-inhibition-bias-lock-design.md):
it is not a near-term body module, feature, ethics controller, or rule judge.
It is an observer-side name for a possible future state where selected trained
inhibitory biases inside existing prediction / suppression / learned-bias paths
are raised, lowered, or locked.

## Deepening (2026-06-02): Prime Directive Corollary 4

This principle ("functions are not feature modules; they emerge from one
substrate") has a sharper sibling now, recorded as **Prime Directive 推论 4**
in `consciousness-stream-architecture.md`:

```text
The object of the work is to make ONE brain complete and self-consistent —
NOT to build a function, NOT to read a function out of the substrate, NOT to
verify a function "emerged".
```

The trap this catches is one layer below "don't build feature modules": even
*reverse-assembling or reading the substrate toward a target behavior* is still
packing life back into a function. The moment a task is framed as "how does the
system do X / explain X / how do we read X out and confirm it emerged", and the
answer assembles substrate pieces to satisfy X — the line is crossed, even when
X is only being *observed* from the observer side.

The legal stance: never aim at any X. Ask only "is the brain complete and
self-consistent — which substrate dynamic is still missing or self-contradictory?"
Complete the self-consistency; behaviors (lesson-taking, pre-planning, live
wavering, recognition, curiosity, expression) emerge on their own, or honestly
do not. We neither build them nor verify them as targets.

Boundary (does not conflict with observer separation): faithfully observing the
*whole* living state is always legal; presupposing a target function and then
reading the substrate to *prove it was achieved* is not. The difference is
"seeing what it actually is" vs. "setting a target then fitting to it".

## Relationship To Existing Top Principles

This principle sits directly below the highest principle and beside the
five-phase life-design frame.

- The highest principle says the target is silicon life, not a program.
- This principle says apparent functions must emerge from one life substrate,
  not from isolated body-side feature modules.
- The five-phase life frame checks whether the emerging pattern preserves
  growth, manifestation, bearing, boundary, and retention balance.
- Tier 0 remains the shared coordinate substrate. Emergent functions do not add
  axes, words, meanings, or fixed world content.

## Legal Function Description

A future design may describe an emergent function only if it can answer these
questions:

1. Which existing substrate traces produce the pattern?
2. Which shared state path carries the pressure, prediction, precision,
   write-out, feedback, residue, or re-entry?
3. Which observer evidence makes the pattern visible without requiring the body
   to print or explain itself?
4. Which boundary prevents the function word from becoming a body ontology
   unit?
5. Which five-phase balance risks are introduced by strengthening this
   pattern?

If these questions cannot be answered, the proposal is only a feature idea, not
an admissible life-substrate design.

## Legal Engineering Shapes

The following shapes are allowed when their boundary is explicit:

- Rust modules as file-level engineering handles.
- Observer-side evidence summarizers.
- Report modes that print bounded numeric evidence.
- Test fixtures that prove a substrate path, as long as they do not pretend to
  be live evidence.
- Body-side numeric state that modulates existing laws without choosing human
  meaning.
- Virtual hardware providers that translate external test setup into numeric
  body facts.

Allowed code may have names that help engineers navigate the repository. Those
names must not be treated as body truth.

## Rejected Engineering Shapes

The following are rejected:

- `FunctionRegistry`, `CapabilityRegistry`, or a body-side feature catalog that
  decides what the system "can do".
- A command controller that selects behavior from function words.
- A request/response surface that turns body life into answer production.
- Independent modules named after external phenomena such as curiosity,
  thought, goal, intention, empathy, repair, understanding, or communication.
- A pipeline where a pattern must receive a functional class before it is
  allowed to exist.
- A body field whose purpose is to store the human-readable function that is
  supposedly happening.
- Tests that protect a feature label rather than a substrate law.

## Admission Rule For New Work

Any future project, spec, plan, code path, or test that claims to add a
function must instead state:

```text
emergent_pattern:
substrate_sources:
shared_state_path:
observer_evidence:
body_ontology_guard:
five_phase_balance_risk:
forbidden_shortcuts:
```

New work should be accepted only when it strengthens the substrate path and
preserves the highest principle, not merely because it adds an externally
useful capability.

## Current Architecture Reading

The current cleaned architecture is mostly compatible with this principle:

- `viewport` is the shared state substrate.
- sensory adapters write numeric evidence rather than semantic claims.
- active reasoning, probe law, prediction pressure, self-development,
  allostatic stability, five-phase evidence, nursery evidence, and surface
  rendering are best read as observer-visible patterns over the same substrate.
- `curriculum_report` and observer tools may print external evidence; they are
  not body speech.

The main design pressure is terminology. Older documents sometimes use words
such as `organ`, `personality`, `ethics`, `owner`, `responsibility`, `function`,
or `module`. Under this principle, those words are admissible only when read as
external design handles or hardware-like channel descriptions, never as
independent body-side ontology.

`responsibility` / `responsible person` has a special boundary: it should be
treated as an innate-bias and accumulated-familiarity effect analogous to
mammalian early caregiver recognition or a domestic animal's hard-to-switch
familiar person bond. It is a natural emergent pattern over bias, exposure,
recurrence, safety, correction history, and continuity. It is not a
post-hoc legal class and not a body-side identity/owner module.

## Acceptance Evidence

A future implementation claiming this principle passes only if:

1. The body remains silent: no `println!`, `eprintln!`, `dbg!`, or human-readable
   diagnostics in body-owned source paths.
2. Rejected semantic-readiness, symbolizer, concept-id, token, label, word,
   naming, identity, owner, ethics, and personality ontology does not enter
   body-owned sources.
3. Function evidence is derived from existing substrate traces, not from a
   feature label.
4. Observer-side reports clearly distinguish deterministic fixtures from live
   runtime evidence.
5. The pattern can be interpreted through five-phase balance without storing
   five-phase words in the body.

Until those checks pass, "function" is only an external proposal word, not a
life-substrate claim.
