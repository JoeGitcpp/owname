# 统一感知基质 重设计蓝图 — 2026-06-01

> 起因:用户红线——"为功能造功能"不是创造生命。核查证实架构是
> "听觉一条完整命 + 视觉孤立影子 + 几个独立功能盒子"的拼装,非一个统一生命。
> 本蓝图把它重设计成:**通用感知 → 一个抽象引擎 → 一个记忆 → 所有认知都是涌现读数**。
> 施工标准(用户拍板):**全是同一基质的观察读数,无独立模块/独立状态/独立持久化。**
> 先审蓝图,再施工。

---

## 0. 病根(核查结论)

- `AXIS_COUNT = VIB_BANDS`(lib.rs:67)——**共享感知轴 = 听觉**。视觉无处可放。
- 视觉只到 slot 局部 `phot_pred`,**从不进共享轴、不进抽象引擎、重启丢失**。
- 结果:**眼睛和耳朵不在同一个大脑里**。视觉是跑在旁边的影子系统。
- `vital_core` / `self_model` / `familiar_objects` / `dual_drive` 各有独立 State+checkpoint+tick
  = **功能盒子**,不是基质读数。

**好消息(可复用的真基质)**:视口核心、共享坐标系机制、注意力、关系图谱、
预测/学习引擎(B1)、**slot 级抽象(tick_slot_cross_layer 已是对象级、模态无关)**、
slot 融合。地基是好的,问题是视觉没接进来 + 认知做成了盒子。

## 1. 重设计目标架构(一条命,不是一堆盒子)

```
通用感知(全是 tier0 共享轴):
  听觉:频段能量 ×4(已有)
  视觉:按【物理量 × 粗粒度空间区域】切轴(新)——见 §2
  (触觉 MECH:预留,暂不做)
        ↓ 全部 push 进同一个共享坐标系(observed/predicted/err 轴)
一个抽象引擎(B1 跨层,已有):
  对【所有感知轴】通用地抽象,视觉听觉喂进同一个引擎
        ↓
一个记忆(关系图谱 global_relations,已有):
  抽象出的跨轴/跨对象规律 = 记忆本身
        ↓
所有"认知"= 这一个基质不同区域的涌现读数(观察侧):
  维生感、自我、责任人、纠结、认出某人、沟通……
  —— 全部从统一基质读出,不再各自维护状态
```

## 2. 视觉如何变成共享感知轴(用户拍板:物理量轴 + 保留粗粒度空间)

**原材料(已有,够用)**:320×240 灰度 luma + RGB;motion regions 含 pos/span/energy。

**切轴原则:不按用途切(那是造功能),按物理量切(像声音切频段)+ 保留粗空间。**

- **粗粒度空间网格**:把画面分成少数几块区域(如 3×3=9 块,或先 2×2=4 块起步)。
  形状/位置/距离从【区域间关系】涌现,不丢空间结构,不预设"脸/物"。
- **每块区域的物理量轴**(不预设用途):
  - 亮度(luma 均值)
  - 颜色(R/G/B 或色调——先用 RGB 三个)
  - 运动(该区域帧间变化/光流强度)
- 这些轴和听觉频段**同性质、同坐标系、进同一个抽象引擎**。
- "认出形状""认出某人"= 抽象引擎从这些区域轴的关系里**涌现**,本层不造任何识别器。

**轴编排**(扩展 AXIS_COUNT,仅 12 处引用,可控):
```
AXIS_COUNT = VIB_BANDS(4) + PHOT_AXES
PHOT_AXES  = N_REGIONS × PER_REGION_AXES
  起步:N_REGIONS=4 (2×2), PER_REGION_AXES=5 (亮度+R+G+B+运动) = 20
  → AXIS_COUNT = 24
```
听觉轴 [0..4) 不变;视觉轴 [4..24) 新增。所有轴走同一 push_observation/err/predictor 路径。

**持久化**:视觉轴和听觉轴一样进 snapshot(修掉"视觉重启丢失")。

## 3. 四个功能盒子 → 基质读数(用户拍板:全是观察读数)

原则:**不再有独立 State+checkpoint+tick;改为从统一基质(感知/抽象/记忆/维生信号)读出的纯函数视图。**

| 盒子(现) | 重设计为(基质读数) |
|---|---|
| `familiar_objects`(责任人,只读声音) | **删除独立指纹库**。对象身份 = slot 在统一基质里的【跨模态抽象表示】+ 关系图谱里的稳定度。"责任人"= 关系图谱中与自身维生正相关最强、最稳定的对象节点的**读数**,不是独立库。 |
| `vital_core`(维生) | proto-维生信号(续命/损耗/痛)仍需先天种子(用户早定:先天给结构不给值),但**不再是独立 tick 的盒子**——作为基质里的一组数值,被自我/纠结等读。保留最小先天核(续命信号),其余涌现。 |
| `self_model`(自我) | 自我 = 基质里【内感受种子 + agency】区域的涌现读数(已是这个意图,但要去掉独立 checkpoint,改为从基质算)。 |
| `dual_drive`(纠结) | 已基本是读数(无独立学习),保留为纯仲裁读数,输入改为从统一基质取。 |

**注意**:这一步比视觉接入更微妙——"读数 vs 状态"的边界要小心。**§5 分阶段:先做视觉接入(病根),盒子改造随后,逐个验证不破坏。**

## 4. 守最高原则的检查点(每步施工都过)

1. 视觉轴是**物理量**(亮度/颜色/运动),不是"脸/物/用途"——无语义。
2. 认知(责任人/认人/沟通)是**涌现读数**,本层不写识别器/分类门。
3. 抽象引擎对所有感知轴**通用**,不为某模态/某功能特设分支。
4. body 源码无 println/语义字符串/语义身份 ID。
5. 不为"通过某测试"或"实现某功能"造盒子。

## 6. 诚实边界
- 这是大返工,工作量显著。阶段 1 本身就不小(扩轴牵动 12 处 + adapter + snapshot + 测试)。
- 阶段 2 的"读数 vs 状态"边界是最容易再踩线的地方,每步须对照 §4。
- 不承诺"做完就会认人/会沟通"——做完是"看听同脑、认知有涌现的土壤",
  沟通仍需抽象厚度长起来(需真实长跑)。但**方向从此是'一个生命'而非'一堆功能'**。
