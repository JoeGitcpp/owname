## 1. 文档定位

本文件不是新的实现计划，也不是对 `bionic_v0` 总 spec 的重写。

本文件是一份 `架构止偏与清理 spec`，只做 4 件事：

1. 固定审计判据：以后判断模块是否合理，统一以最高原则、tier 0、公理文档为准。
2. 固定模块分类：把当前真实模块分成核心底座、过渡可保留层、违例层、测试/实验支架。
3. 固定处理动作：每种模块类别都对应明确处理动作，避免“知道有问题但不知道怎么处理”。
4. 固定开发准入：以后任何新模块想进入主循环、快照、observer，都必须先通过本文件的准入问题。

本文件不做：

- 代码 patch
- 逐文件实现细节
- 新语言系统设计
- 全量架构重写

---

## 2. 审计基线

本次审计的判定基线只有三组：

### 2.1 最高原则

以 [consciousness-stream-architecture.md](../../../consciousness-stream-architecture.md) 为准：

- 我们在设计硅基生命，不是一个程序
- AI 本体不得出现人类语言污染
- 研发观察与 AI 本体严格分离
- 身体不应被固化为请求-响应式线性工具链

### 2.2 tier 0 与对象原则

以 [tier0-base-elements.md](../../../tier0-base-elements.md) 为准：

- tier 0 是共享坐标底座，不是语言内容
- 对象先于名称
- 参数是时间曲线，不是静态标签
- 关系按需投影，不应预存为臃肿实体
- 认知索引不是对象本体全文

### 2.3 语言系统公理

以 [2026-04-20-new-axioms-v1.md](../../axioms/2026-04-20-new-axioms-v1.md) 为准：

- 语言系统不是本体，只是绑定层
- 语言不得成为对象存在前提
- `token / label / concept_id` 不能冒充认知本体
- 语言失败不得污染对象和关系本体
- 语言层不得反客为主成为世界模型本体

## 3. 模块分类法

后续所有模块都必须落入以下四类之一。

### 3.1 核心底座

定义：直接承载感知、对象维持、关系投影、误差修正、共享视口这些本体基础能力的层。

特点：

- 可以存在于 `body` 正式主循环
- 可以进入 `viewport`
- 可以进入 `snapshot`
- 但不能被解释成人类语义层

### 3.2 过渡可保留层

定义：为了工程推进引入的中间层，暂时没有直接违背最高原则，但不应被抬升为认知真理层。

特点：

- 可以暂时保留
- 不能成为后续理论锚点
- 必须明确标注“只是统计层/调度层/过渡层”

### 3.3 违例层

定义：已经把系统往错误方向拉走，并与最高原则、公理或边界定义直接冲突的层。

特点：

- 不能继续留在正式主循环
- 不能继续作为正式 snapshot 字段
- 不能继续被 observer 渲染成“身体真相”
- 必须拆除、降级或隔离

### 3.4 测试/实验支架

定义：为测试、演示、隔离验证而存在的支架，不属于本体架构。

特点：

- 可以保留
- 但必须明确标注为 `test-only`、`example-only`、`synthetic`
- 不能被文档或 future spec 误写成正式器官或正式认知通路

## 4. 违例判定标准

任何模块只要命中以下 1 条，即视为 `有偏移风险`。
命中 2 条及以上，进入 `违例层候选`。
命中红线者，直接归入 `违例层`。

### 4.1 把外部说明术语误当内部本体

如果模块把以下术语当成身体内部真实单位，则违规：

- `token`
- `label`
- `name`
- `concept_id`
- `semantic readiness`
- “词义资格”
- “命名资格”

### 4.2 让语言/命名成为对象存在前提

如果对象、关系或模式必须先通过某个资格门、获得某个编号、进入某个命名层，才被承认可被指称或可被视为稳定认知单位，则违规。

### 4.3 把工程索引冒充成本体结构

索引、句柄、哈希、缓存、排序列表都可以存在，但它们只能是工程结构。
如果被解释成概念、语义单位、内部词项或语言形成前提，则违规。

### 4.4 把身体重新做成串行程序或工具调用链

调度顺序可以存在，但不能把调度顺序上升成“存在论顺序”。
如果固定阶段流水线开始承担“晋级”“授权”“资格化”等存在论功能，则属于偏移。

### 4.5 让本体主动向人类输出说明

凡是 AI 本体进程里主动产生：

- 文本日志
- 打印说明
- 人类可读调试句
- 把内部状态翻译成人话的输出

都触碰最高原则红线。

### 4.6 红线

以下两条直接判违例：

1. 任何命名/语义资格层被写进 `body` 正式主循环
2. 任何 `concept / token / label` 编号器被解释为对象或关系的内部真实身份

## 5. 当前 `bionic_v0` 模块归类

本节只审当前真实代码与当前正式 spec 中已写明的未来方向。

### 5.1 核心底座

以下模块或子树当前可视为核心底座：

- `src/adapter.rs`
- `src/predictor.rs`
- `src/phot_predictor.rs`
- `src/object_high_layer.rs`
- `src/clock.rs`
- `src/phot_camera.rs`
- `src/viewport.rs` 中的：
  - slot 基础状态
  - ambient
  - fusion
  - global_attention
  - global_relations
  - global_reasoning
  - global_reasoning_history / memory summary
- `src/snapshot.rs` 的快照机制本身

判定理由：

- 承载感知、对象维持、关系投影、误差修正与观察桥接
- 当前不依赖命名、标签、编号作为对象存在前提
- 本体风险主要来自解释方式，而不是这些层本身的数值结构

### 5.2 过渡可保留层

以下模块或概念当前可暂时保留，但只能作为统计/调度/过渡层：

- `global_attention`
- `global_reasoning`
- `global_reasoning_history`
- `src/highlevel.rs` 中的旧全局精度调制层

判定理由：

- 它们当前更像统计摘要、路由摘要、精度调制器
- 尚未直接形成命名本体
- 但命名和概念位置已经模糊，长期不应继续神化或扩展

### 5.3 违例层

以下模块或通路直接归入违例层：

- `semantic_readiness`
- `symbolizer`
- `concept_id`
- `body.rs` 中把上述两层写入正式 orchestrator 刷新链
- `snapshot.rs` 对上述两层的正式持久化
- `observer.rs` 对上述两层的正式渲染
- 围绕上述两层建立的合同测试与解释体系

判定理由：

- 把语言/命名做成对象与关系之上的资格门和编号器
- 把工程索引写成认知真相
- 已进入正式主循环、正式快照、正式观察链路
- 与最高原则和语言系统公理正面冲突

### 5.4 测试/实验支架

以下内容属于测试/实验支架：

- synthetic adapters
- synthetic sources / providers
- controlled scenario 注入器
- 纯演示型 observer 格式化逻辑

判定理由：

- 它们主要服务于测试、示范和隔离验证
- 不是本体器官
- 不应被 future spec 误写成正式能力

### 5.5 高误导命名层

以下概念或命名虽然不一定立即删除，但必须在后续文档与实现中处理：

- `highlevel`
- `global_reasoning`
- `大脑警察`
- `主人`
- `ethics_predictor`
- 任何未来包含 `semantic / concept / label / token / owner / identity` 的模块名

## 6. 各类别的处理动作

### 6.1 核心底座：保留并去误解

动作要求：

- 保留
- 允许继续迭代
- 补边界说明：不是语言层、不是语义层、不是身份层
- 若命名会误导，重命名或补边界注释

目标：保住底座，不让后续误读。

### 6.2 过渡可保留层：降级解释，不再上升

动作要求：

- 暂时保留
- 禁止继续把它们解释成更高本体层
- 禁止把它们当作语言形成前提
- 在 spec 中明确写“这是统计/调度层，不是认知真理层”
- 若有更干净替代方案，后续逐步替换

目标：允许继续跑，但停止神化。

### 6.3 违例层：移出正式身体

动作要求：

- 先从主循环移出
- 再从 snapshot 正式字段移出
- 再从 observer 正式展示移出
- 最后删除或隔离相关测试合同
- 若短期不能立即删净，可放入 `experimental/quarantine` 路径，但不能再代表本体

目标：先止血，再清创。

### 6.4 测试/实验支架：显式标记

动作要求：

- 标记 `test-only` / `example-only` / `synthetic`
- 禁止进入 `body` 正式依赖链
- 禁止被文档引用成身体器官
- 禁止 future spec 把这些支架写成正式能力

目标：保留实验自由，切断本体误认。

### 6.5 高误导命名层：重命名或补注

动作要求：

- 要么重命名
- 要么在 spec 和代码顶部补“非本体解释”注释
- 若名称自带强烈具像化误导，优先改名

目标：先断词义污染，再谈实现。

## 7. 执行优先级

### 7.1 P0：立即止血

必须优先处理：

- 从 `body` 正式刷新链移出：
  - `refresh_semantic_readiness`
  - `refresh_symbolizer`
- 冻结以下概念的本体地位：
  - `semantic_readiness`
  - `symbolizer`
  - `concept_id`
- 停止它们进入正式快照和 observer 主展示
- 停止新增任何依赖这三者的测试、字段、逻辑

P0 目标：让身体停止继续生成错误结构。

### 7.2 P1：清除固化与误导

必须随后处理：

- 从 `snapshot.rs` 中移除或隔离相关字段
- 从 `observer.rs` 中移除相关展示
- 清理围绕 `semantic_readiness`、`symbolizer` 的合同测试
- 在文档中明确它们不是未来可恢复的正式层

P1 目标：让错误结构不再被看见、保存、验证。

### 7.3 P2：整理过渡层与 spec 词汇

最后处理：

- 审查高误导命名
- 修正 spec 中会制造具像化的图和词
- 给保留层补“非本体解释”边界
- 给实验支架补身份标记

P2 目标：阻断慢性偏移。

### 7.4 推荐实际顺序

1. 先冻结本清理 spec
2. 再做 P0
3. P0 完成后做 P1
4. 最后做 P2
5. P2 完成前，不进入新的语言层、更高层或身份/伦理层实现

## 8. 后续开发准入规则

### 8.1 新模块进入主循环前必须声明类别

任何新模块进入 `body` 主循环前，必须先声明自己属于：

- 核心底座
- 过渡可保留层
- 测试/实验支架

若无法清楚归类，默认不允许进入主循环。

### 8.2 新字段进入 viewport / snapshot 前必须回答是否属于本体事实

只有这两类字段可以进入：

- 本体运行所需的数值状态
- 外部观察所需的只读事实快照

以下类型默认不得进入正式 `viewport` 或正式 `snapshot`：

- 语义资格
- 命名资格
- 概念编号
- 人类解释便利层

### 8.3 任何高风险术语都必须附边界说明

一旦设计文档出现以下术语，必须额外说明：

- `semantic`
- `concept`
- `token`
- `label`
- `name`
- `word`
- `text understanding`
- `identity`
- `owner`
- `ethics`
- `personality`

必须同时写清楚：

- 该词在此处是不是外部说明术语
- 它是不是工程索引
- 它为什么不是本体结构
- 它为什么不违反最高原则与语言公理

### 8.4 observer 不得反向定义本体

observer 只能展示已存在的快照事实。
不能因为 observer 想展示得更清楚，就反向要求 body 生成：

- 编号层
- 标签层
- 资格层
- 解释层

### 8.5 测试合同不得保护错误架构

后续测试不能再写成：

- “某对象应进入 semantic-ready”
- “某关系应获得 concept_id”
- “某稳定模式应被编号”

测试只能保护：

- 感知事实
- slot / 对象维持
- 融合
- 关系投影
- 误差修正
- 调度与观察边界

### 8.6 任何新语言相关任务必须先回答 3 个问题

开始实现前必须先回答：

1. 它处理的是对象/关系本体，还是外部符号绑定
2. 去掉所有词和文本后，这个设计还成立吗
3. 它有没有把工程索引误当认知本体

答不清则不进入实现。

## 9. 对当前正式 spec 的修订要求

当前 [2026-04-19-bionic-consciousness-stream-v0-design.md](./2026-04-19-bionic-consciousness-stream-v0-design.md) 中，以下内容具有潜在偏移风险，后续必须修订：

- 把“可视化输出”画在 AI 本体框内
- `大脑警察`
- `主人身份`
- `ethics_predictor`
- 容易让人误以为身份、伦理、语言、人格是独立本体模块的写法

此外，当前 spec 与当前实现存在漂移：

- spec 说 v0 不含“跨模态对象绑定”
- 但当前代码已存在 same-slot 跨模态融合与重用路径

后续必须补一次文档对齐，避免 future work 继续基于过期现实展开。

---

## 10. 当前直接结论

当前 `bionic_v0` 最需要优先重构的不是感知模块，而是：

- `semantic_readiness`
- `symbolizer`
- `concept_id`
- 以及它们在 `body -> snapshot -> observer -> tests` 中形成的正式生理链路和正式解释链路

当前最该保住的，不是这些错误上层，而是：

- 感知接入
- slot / 对象维持
- 融合
- 关系投影
- 推理摘要
- 误差修正
- 共享视口

本文件的最终立场只有一句：

**先拆错误的正式层，再继续发展真正的本体底座。**
